# 知识点掌握率重新设计方案（多知识点题不再"连坐"）

> 状态：**待评审，未实施**。本文只做设计，不改动任何代码。
> 触发问题：一道题挂多个知识点时，答错会让"被顺带考到"的知识点被莫名扣分；而学生把以该知识点为主知识点的题全部做对，又无法把分数提回来。

## 二、根因：三条不对称

### 不对称 1 · 证据不可逆（"扣得动、练不动"）

- **扣分侧**：`services/scoring.quiz_accuracy_by_kp` 把一道题"摊"给它挂的所有标签：
  主 KP 权重 1.0、其它标签权重 `SECONDARY_KP_WEIGHT = 0.3`（`scoring.py:30`、`scoring.py:87-94`）。
  于是主 KP = A、标签含 B 的题答错 → **B 的正确率分子分母都被污染**。
- **提升侧**：组卷只按主 KP 匹配 —— `practice.py:243` `q.filter(Question.kp_id.in_(target_kps))`
  （`weak` / 靶向 / `random` 模式都是同一行口径，另见 `practice.py:183`、`:263`）。
  B 没有专属题 → 抽到 0 道题 → **学生无论做什么都改不动 B**。

一侧能扣、另一侧不能加，同一个知识点上就出现了单向棘轮。

### 不对称 2 · 证据强度与"可练性"错配

连坐证据按 0.3 永久停留在历史里；而正面证据只在专属题上产生。对 KP018 这种"0 专属题 / 24 道连带题"的知识点，
其数值完全由"别人的题"主导 —— 学生答对再多它也上不去。`2026-09-24` 那次"不再扩散到同章"的收紧
（`practice.py:232-248`）把靶向范围收窄到主 KP，客观上让这个问题从"抽错题"变成"抽不到题"。

### 不对称 3 · 同一事实存在三套口径

| 口径 | 实现位置 | 特征 | 消费方 |
|---|---|---|---|
| A · 加权混合 | `services/scoring.quiz_accuracy_by_kp` | 按题去重 + 主 1.0 / 次 0.3 | 预警、靶向范围、掌握率数字 |
| B · 原始计数 | `routers/graph.py:351 _mastery_from_records` | **不去重**、只看 `answer_records.kp_id`、**不含次要** | 图谱节点配色、学习路径 `quizMastery`、学情矩阵 `quizMastery` |
| C · 取大值 | `services/kp_stats.mastery_by_kp:35` | `max(答题正确率A, 资源完成率)` | 综合掌握率、`learning_paths.mastery`、驾驶舱、干预报告 |
| B' · 内联复制 | `routers/teacher.py:657-668` | 又抄了一份 B（未调用函数） | 教师端掌握热力图 |

同一知识点在"掌握率数字"（A/C）和"图谱颜色"（B）上给出不同结论，用户感受同样是"莫名"。

## 三、新口径定义：主证据定分 + 相关证据只作提示

核心原则：**打分只认"这道题是不是奔着这个知识点来的"；顺带考到的只作诊断提示，不参与打分。**

### 3.1 两类题目

```
专属题(kp)  = questions where  kp_id  == kp          # 这道题的主 KP 就是它
相关题(kp)  = questions where  kp ∈ kp_ids 且 kp_id != kp   # 顺带考到它
```

### 3.2 掌握率取值（三分支，带 basis 标记）

```python
def kp_mastery(db, user_id, kp, course_id=None):
    # 只取「按题去重、每题最近一次作答」
    if 专属题.已作答数 > 0:
        value = 专属题.答对数 / 专属题.已作答数
        basis = "primary"          # 实测值：学生自己为这个知识点做的题
    elif 相关题.已作答数 >= ENGAGE_MIN:
        value = 相关题.答对数 / 相关题.已作答数
        basis = "related"          # 参考值：题库暂无专属题，明确标注来源
    else:
        value = None               # 无可评测证据，不编造 0，也不标"已掌握"
        basis = "none"
    return value, basis
```

**单调性保证（这是"能练回来"的数学依据）**：
`basis == "primary"` 时，分子分母只含专属题。学生每答对一道专属题 → 分子 +1（分母 +1 或不变）→ 数值**单调不减**；
并且其它题目的对错**不再进入**它的分子分母 → 连坐消失。

### 3.3 连坐信号去哪了（不丢，只是不再改分数）

相关证据保留为独立的诊断字段，用于：
- 前端提示：「该知识点还有 N 道题会顺带考到它」；
- 归因/错题分析：「这道题同时考了 A 和 B」，解释学生错因归属；
- 靶向组卷的可选加练范围（见 5.2）。

## 四、函数契约（建议）

新增在 `services/scoring.py`，替换现有 `quiz_accuracy_by_kp` 作为**唯一掌握率入口**：

```python
@dataclass
class KpEvidence:
    kp_id: str
    basis: str               # "primary" | "related" | "none"
    mastery: float | None    # basis=none → None（不是 0）
    # 专属题（打分依据）
    primary_total: int       # 题库中该点的专属题总数
    primary_answered: int    # 该生作答过的专属题数（按题去重）
    primary_correct: int
    # 相关题（诊断 + 兜底依据）
    related_total: int
    related_answered: int
    related_correct: int
    related_wrong: int       # 被连坐答错的题数（提示用）
    # 预警门槛用
    eligible: bool

def kp_evidence(db, user_id, course_id=None) -> dict[str, KpEvidence]
def kp_mastery(db, user_id, course_id=None) -> dict[str, float | None]
```

关键实现约束：
1. **按题去重取最近一次**：沿用现有 `group_by(AnswerRecord.q_id)` + `max(AnswerRecord.id)` 的写法（`scoring.py:53-61`），这部分逻辑正确，保留。
2. **课程隔离**：新增可选 `course_id` 参数，顺带修掉 `待修复清单.md` P43（两个统计函数当前无 course 参数）。默认 `None` = 现状，逐一改 4 个消费方。
3. **旧的加权口径保留但不再默认启用**：`quiz_accuracy_by_kp(secondary_weight=...)` 作为对账/回退入口保留（现有参数就是为此留的），文档标注 deprecated。
4. 题量小（228 条），直接一次取回本课程题目在内存里分流即可，不引入 SQL 方言技巧。

## 五、必须同步的连带改动

只改 `scoring.py` 不够，下面三处不同步改，问题依旧会以别的形式冒出来。

### 5.1 预警门槛（**必改**）

`alert_detector.py:35` `ENGAGE_MIN = 2`，判定用 `scoring` 返回的第二个元素 `n`，而该 `n` **含次要命中**
（`scoring.py:89` `hits[kp] += 1`）。不改的话：KP018 会因为 24 道连带题被拉进预警候选，
而学生**从没练过它** —— 属误报。

新规则：`eligible = (basis=="primary" and primary_answered >= 2) or (basis=="related" and related_answered >= 2)`。
同步影响 `teacher.py:1036-1044`（预警"重新确认"的判级入口）。

### 5.2 组卷范围（**必改**，否则第三分支永远用不上）

`practice.py:243`、`:263` 的 `Question.kp_id.in_(target_kps)` 改为 **专属题 ∪ 相关题**：

```python
scope = primary_targets | related_targets      # related 由 kp_ids 精确匹配得到
# 排序：专属题优先，其次相关题（_order_pool 的 tier 前置 0/1）
```

- 实现方式（**推荐，零表结构变更**）：本题库量级小，直接 `filter(course, published).all()` 后

- 备选：新增映射表 `question_kp_tags(q_id, kp_id)`。**建表属表结构改动，须先经你同意**，本文不预设。
- 同时 `practice.py:66-91 _random_scope_kp_ids` 的 `rate < 100` 判定要换成新口径，
  否则"分数由连坐压到 100 以下"的知识点会被反复抽进随机练习。
- `practice.py:206-210`（kp-pool 只统计主 KP）需一并改为"专属题数 + 相关题数"，用于前端提示"该点暂无可练专属题"。

### 5.3 消灭 B / B' 口径（**必改**，否则图谱颜色还是旧账）

## 附：一句话总结

把「答对了这道题」和「这道题涉及哪些知识点」分开：**打分只认专属题，顺带考到的只作提示**；
没有专属题的知识点**诚实地显示"暂无评测"**，并通过放宽组卷范围让它**有题可练**。
这样"一道题错就莫名扣子知识点"从根上消失，"做对专属题就能提升"成为可验证的单调性质。
