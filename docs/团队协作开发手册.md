## 1. 两个数据口径（最容易混淆，务必分清）

全系统严格区分两个"率"，**混用会导致文案与数值对不上**：

| 概念 | 英文 | 数据来源 | 当前可用性 | 展示位置 |
| --- | --- | --- | --- | --- |
| **学习完成率** | completion / mastery | `learning_paths.mastery`（资源学习进度聚合） | ⚠️ 代码可用，但当前全为 0 | 学习路径、学情矩阵左列、热力图（默认）、驾驶舱指标 |
| **知识掌握率** | quizMastery | `answer_records` 答题正确率 | ⚠️ 代码可用，但记录太少 | 学情矩阵右列、热力图（切换）、练习模块 |

> ⚠️ **当前两者都"空转"**：`learning_paths` 共 408 条**全部 `status='todo'`**，`answer_records` **仅 2 条**。算法是真实的（见 `services/alert_detector.py`、`routers/graph.py`），缺的是输入数据。**这不是 bug，不要当 bug 修**——详见 `项目真实交互梳理.md`。

**计算函数**（`backend/app/routers/graph.py`）：

```python
_resource_mastery(user_id, db)      # 资源学习完成率：知识点下所有资源进度的平均值
_mastery_from_records(user_id, db)  # 答题正确率：answer_records 中 is_correct 的占比
_mastery_for_user(user_id, db)      # 当前 = _resource_mastery（题库导入后应改为两者取大）
_quiz_mastery_for_user(user_id, db) # 当前 = _mastery_from_records
```

**状态判定**（`_status_from_quiz_mastery`）：

```
资源学习完成率 ≥ 100%  →  done（已完成）
已答题（has_quiz=True）：
    ≥80%  →  done      ≥50%  →  doing      <50%  →  warn（含全错 0%）
未答题：
    资源进度 > 0%  →  doing             = 0%  →  todo（未开始）
```

**前端文案对照**：

| status | 前端显示 | 进度条颜色 |
| --- | --- | --- |
| `done` | 已完成 | `excellent`（绿） |
| `doing` | 学习中 | `fair`（黄） |
| `warn` | 待加强 | `weak`（红） |
| `todo` | 未开始 | `none`（灰） |

> 新增任何"能力评估"类指标时，**必须明确它属于上述哪个口径**，并在前端文案中区分，不要笼统称"掌握率"。

## 2. 进度保存：不回退原则

`POST /api/v1/student/resources/{res_id}/progress` 采用**取最大值**策略：

```python
p.progress = max(prev_progress or 0, progress)
p.position = max(prev_position or 0, position)
```

**原因**：学生看完视频（100%）后重复播放，中途的 `timeupdate` 事件会带着低 position 上报，若直接覆盖会把 100% 重置。前端也有防御（`resource.js` 中已完成资源强制按 100% 上报）。

> **新增任何进度上报逻辑时，必须遵守不回退原则。**

## 3. 数据模型

### 3.1 表清单（23 张）

| 分类 | 表 | 说明 |
| --- | --- | --- |
| **用户** | `users` / `classes` / `teacher_classes` | 账号、班级、教师-班级关联 |
| **课程** | `courses` / `resources` / `resource_progress` / `resource_study_log` | 课程、资源、进度、时长日志 |
| **图谱** | `graph_nodes` / `graph_links` / `kp_details` / `learning_paths` | 图谱节点/边、知识点详情、学习路径（**核心表**） |
| **练习** | `questions` / `practice_sessions` / `answer_records` | 题库、练习会话、答题记录 |
| **AI** | `chat_sessions` / `chat_messages` | 对话会话与消息 |
| **智能体** | `st_question_drafts` | 出题草稿（个人，未发布不进正式题库） |
| **预警** | `alerts` / `messages` | 学习预警、私信/通知 |
| **干预** | `interventions` / `intervention_templates` / `reports` / `teacher_class_data` | 干预、模板、报告、班级聚合（**`teacher_class_data` 当前无人有效读取**） |
| **其他** | `study_checkins` | 学习打卡 |

### 3.2 核心表：`learning_paths`

**全系统数据枢纽**，学生端路径、学情矩阵、教师端热力图/驾驶舱都读它。

| 字段 | 说明 |
| --- | --- |
| `user_id` + `kp_id` | 联合业务主键 |
| `step` | 学习顺序 |
| `name` / `chapter` | 知识点名 / 章节 |
| `status` | `todo` / `doing` / `done` / `warn` |
| `mastery` | **学习完成率** 0-100（资源进度聚合） |
| `progress` | 同 mastery（冗余，保持一致） |
| `res_count` | 挂载资源数 |
| `locked` / `lock_reason` | 锁定状态 |

**同步时机**：`POST /student/resources/{res_id}/progress` → `_sync_lp_from_resource_progress()` 实时回写。

### 3.3 核心表：`answer_records`

| 字段 | 说明 |
| --- | --- |
| `user_id` / `q_id` / `kp_id` | 学生、题目（→ `questions.q_id`）、知识点 |
| `is_correct` | 是否正确（0/1） |
| `my_answer` / `correct_answer` | 答案 |
| `created_at` | 时间 |

> 该表数据量直接决定"知识掌握率"是否有意义。**当前仅 2 条**，是首要补齐目标。

### 3.5 资源文件路径规范（2026-09-11 定）

| 项 | 值 |
| --- | --- |
| 磁盘根目录 | 项目根 `resources/`（不入 Git，需网盘/移动介质分发） |
| 资源文件 | `resources/{course_id}/{res_id}/{文件名}` —— 每个资源独占目录 |
| 封面 | `resources/covers/{res_id}.jpg` |
| 访问 URL | `/resources/{course_id}/{res_id}/{文件名}`（与磁盘一一对应，由 `main.py` 挂载） |

规则：

- **所有资源一律由教师上传添加**（"内置资源目录 + 扫描自动登记"机制已废除，`import_course_resources.py` 已删除）；

- 一致性由启动日志 `[resource-verify]` 报告（断链记录 / 孤儿文件）；旧数据迁移用 `backend/migrate_resource_paths.py`（幂等）；
- 旧前缀 `/assets/resources` 已移除兼容挂载——访问 404 即说明该环境数据未迁移。

## 4. 协作流程

### 4.1 接口变更流程（强制）

```
1. 提出方说明：改什么、为什么、影响哪些页面
2. 评审通过
3. 后端改 → 更新《接口文档》契约
4. 前端改 → 联调
5. 双方确认后合并
```

> ⚠️ **禁止未经通知改接口字段名**。历史上 `teacher/classes` 返回数组 vs `{list:[]}` 不一致导致过 Bug。
> 已发生的契约变更（如 `/question/gen` 由 JSON 改为 SSE）必须在《相较v1.0的改动.md》中标注**【破坏性】**。


- 主干保护：禁止直接 push `main`，走 feature 分支 + PR。

## 5. 红线与常见坑

### 5.1 🔴 绝对不能做的事

| 红线 | 原因 |
| --- | --- |
| **接口返回不套 `ok()` / `fail()`** | 前端 `res.code !== 0` 判断失效，页面静默失败 |
| **改 `/ai/chat` 等 SSE 事件字段** | 前端 `chat.js`/`question.js` 已依赖 `content`/`citations`/`outOfScope`/`draft` 等事件名 |
| **渲染用户输入不 `U.esc()`** | XSS 漏洞 |
| **硬编码颜色值** | 换肤失效、主题不一致 |
| **提交 `assets/resources/`（1.7GB）到 Git** | 仓库爆炸，所有人 clone 失败 |
| **把 API Key / `JWT_SECRET` 提交到 Git** | 安全泄露（`.env` 已被 gitignore） |
| **直接改 `learning_paths.mastery` 而不走同步函数** | 数据不一致 |
| **删除 `regression_test.py` 中的用例来"让测试通过"** | 掩盖问题 |
| **绕过 `API.*` 直接 `fetch`** | 拿不到统一注入的 JWT（`question.js:558` 已因此产生 401 bug） |
| **手写资源磁盘路径拼接** | URL 前缀 `/resources` 与磁盘 `resources/` 是一一对应的，反解一律用 `media_utils.url_to_path()`；手写拼接曾导致删除资源找不到文件、静默产生孤儿文件 |

### 5.2 ⚠️ 常见坑（已踩过，别再踩）

| 坑 | 现象 | 规避 |
| --- | --- | --- |
| **进度被 `min(99, ...)` 卡住** | PPT 看到最后一页只能到 99% | 所有百分比上限用 **100**，不用 99 |
| **进度回退** | 视频重复播放进度被重置 | 保存时 `max(历史值, 新值)` |
| **返回数组 vs `{list:[]}`** | 教师端班级下拉为空 | 前端 `Array.isArray(r) ? r : (r.list \|\| [])` |
| **HTML 引用已删除的 JS** | 页面加载慢/超时（404 等待） | 加 script 前确认文件存在 |
| **分母只算"有数据的"** | 指标虚高（83.3% 实际 3.7%） | 率的计算必须**含未开始的 0%** |
| **两个"掌握率"混淆** | 文案说学习完成率，数值是答题正确率 | 严格区分第 1 节两个口径 |
| **除法未防零** | `ZeroDivisionError` | `round(a/b, 1) if b else 0` |
| **前端改完不生效** | 浏览器缓存 | `Ctrl+Shift+R` 强刷（后端已加 NoCache） |
| **测试污染数据库** | 回归后数据异常 | 跑完测试清理 + 重新生成备份 |
| **`_mounted` 导致页面不刷新** | 二次进入视图数据不更新 | 实现 `update()` 方法 |
| **`git rm` 批量删中文路径** | 可能误删整个目录 | 逐文件 `rm`，删后立即 `ls` 验证 |

### 5.3 已知技术债（待治理）

| 债务 | 影响 | 建议 |
| --- | --- | --- |
| `routers/teacher.py` 2116 行 | 难维护、易冲突 | 拆为 `teacher` / `question` / `analysis` 子路由 |
| **无数据库迁移工具** | 改表结构要删库重建（`database.py` 有手写 `_migrate()` 兜底） | 引入 Alembic |

| 前端无构建/无类型检查 | 大型改动易出错 | 可选引入 JSDoc / TS 检查 |
| 无 CI/CD | 人工测试 | GitHub Actions（可选） |

| 资源文件与数据库无一致性校验 | 用基准快照恢复数据库会产生孤儿文件（磁盘有、DB 无） | 增加启动时孤儿扫描 |

## 6. 数据库基准与同步（**必读**）

> **为什么题库会"对不上"**：正式题库存在 SQLite 数据库（`backend/app/data/course_agent.db`）中，而该文件被 `.gitignore` 忽略、**不随 git 传播**。git 上只走"原料与配方"（`after_class.json` 题库源 + `kp_section_mapping.json` 知识点映射 + 导入脚本）。本地数据库停留在旧状态时，题库自然与最新代码对不上。

### 6.1 随 git 传播的内容

| 文件 | 说明 |
| --- | --- |
| `backend/app/data/st/st_bank/after_class.json` | 课后题库源（228 题，导入原料） |
| `backend/kp_section_mapping.json` | 王道小节 → 知识点 KP 映射（人工维护） |
| `backend/app/data/st/rag.db` | RAG 向量库（1480 切片，二进制随库走） |
| `backend/import_st_bank.py` / `run_st_ingest.py` | 题库导入 / RAG 构建脚本 |
| `backend/app/data/course_agent.db.bak.baseline` | **基准数据库快照**（2026-09-08） |

> 其中 `rag.db` 虽然随 git 走，但**不适合**放二进制大文件——见 §5.3 技术债。

### 6.2 同事首次同步 / 题库对不上时的恢复步骤

```bash
git pull
cd backend
# 方式一（推荐）：直接用基准快照恢复，与本机开发状态完全一致
python -c "import shutil; shutil.copy('app/data/course_agent.db.bak.baseline', 'app/data/course_agent.db'); print('已恢复基准数据库')"
# 方式二：保留本地数据，仅重建题库（导入是幂等的，会按最新映射刷新全部 KHD 题）
python import_st_bank.py
```

方式一恢复后的基准状态：**229 题**（228 道 KHD 课后题 + 1 道 AI 生成发布题 AI001），无占位种子题。

方式二适用于本地已有练习/答疑等想保留的数据——它只刷新题库归属（`kp_id`/`kp_path`），**不会删除历史残留的占位种子题**（Q1024/Q1025/Q1026/Q2001~Q2010），需另行清理：

```bash
python -c "from app.database import SessionLocal; from app.models.question import Question; db=SessionLocal(); n=db.query(Question).filter(Question.q_id.in_(['Q1024','Q1025','Q1026']+[f'Q200{i}' for i in range(1,10)]+['Q2010'])).delete(synchronize_session=False); db.commit(); print('已清除占位种子题:', n); db.close()"
```

### 6.3 日常约定

- `course_agent.db`、历史 db 备份与**教师个人出题草稿 sidecar**（`st/drafts/`）**不入仓库**（gitignore 已覆盖）；提交只针对 `.bak.baseline` 基准快照与 `rag.db`
- 当题库/映射/图谱发生**阶段性变更**需要同步给全队时：更新 `course_agent.db.bak.baseline` 副本并单独提交，提交信息注明变更内容
- 提交快照前先跑一遍 `python import_st_bank.py`，确认题库状态可由脚本复现
- 草稿箱（`st_question_drafts`）是教师个人数据，不要求全员一致
