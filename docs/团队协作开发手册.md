## 1. 项目概述

### 1.1 一句话定位

面向《数据结构》课程的 **AI 驱动教学辅助系统**：为学生提供个性化学习路径、资源学习、智能练习与 AI 答疑；为教师提供班级学情监测、薄弱点归因、教学干预与 AI 出题。

### 1.2 两端功能全景

**学生端（7 个页面）**

| 路由 | 页面 | 核心能力 |
|---|---|---|
| `#dashboard` | 学习驾驶舱 | 核心指标环形图、今日任务、学习路径概览 |
| `#graph` | 课程图谱导航 | 知识图谱可视化、知识点详情、前置关系 |
| `#resource` | 学习资源中心 | 左侧学习路径 + 右侧资源卡片、视频/PPT/PDF 学习 |
| `#ai` | AI 智能答疑 | 多教学方法对话、引用溯源（**待 AI 接入**） |
| `#practice` | 智能练习 | 练习模式、答题、错题本 |
| `#mastery` | 我的学情 | 知识点矩阵（资源完成率 + 知识掌握率双列） |
| `#alerts` | 预警与提醒中心 | 学习预警、教师私信、系统通知 |

**教师端（7 个页面）**

| 路由 | 页面 | 核心能力 |
|---|---|---|
| `#dashboard` | 教学驾驶舱 | 班级总览、薄弱知识点排行、待办事项 |
| `#monitor` | 学情监测看板 | 热力图（学习完成 / 知识掌握可切换）、学生个体详情、预警复核 |
| `#analysis` | 归因与错题分析 | 错题分布、薄弱关系链 |
| `#question` | AI 出题与题库管理 | 题库 CRUD、AI 生成习题（**待 AI 接入**） |
| `#intervention` | 教学干预与策略 | 干预策略生成、执行跟踪、效果复测 |
| `#report` | 学情分析报告 | 报告生成与导出 |
| `#resource` | 资源管理 | 资源上传、知识点挂靠 |

### 1.3 当前完成度（交接时的真实状态）

| 模块 | 状态 | 说明 |
|---|---|---|
| 非 AI 业务接口 | ✅ **全部真实可用** | 数据均从关系表实时计算，无 mock |
| 学生端页面 | ✅ 完成 | 7 个页面功能闭环 |
| 教师端页面 | ✅ 完成 | 7 个页面功能闭环 |
| 课程资源 | ✅ 65 个 | 数据结构 1-9 章，含视频/PPT/教材 |
| 知识图谱 | ✅ 9 章 34 知识点 | 含前置关系 |
| **AI 智能答疑** | ⚠️ **mock 兜底** | 关键词匹配预设答案，待接入 LLM + RAG |
| **AI 出题** | ⚠️ **题库筛选** | 从现有题库随机抽题，非真正生成 |
| **题库** | 🔴 **严重不足** | **仅 13 道题**，覆盖 34 个知识点 |
| 答题记录 | 🔴 几乎为空 | 全库仅 1 条，导致"知识掌握率"全为 0 |

> **⚠️ 交接前必读**：项目当前最大的两个缺口是 **① AI 能力未接入** 和 **② 题库严重不足（13 题 vs 34 知识点）**。这两点直接决定了第 9 章的分工设计。

## 2. 快速上手

### 2.1 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Python | **3.12**（推荐）/ 3.11+ | 后端运行时 |
| Node.js | 18+ | **仅运行 E2E 测试需要**，前端本身是静态文件，无需构建 |
| 浏览器 | Chrome / Edge | 前端无构建步骤，直接打开即可 |
| 操作系统 | Windows（当前） / macOS / Linux | 路径注意跨平台兼容 |

### 2.2 三步启动

**方式一：一键启动（推荐，Windows）**

双击项目根目录的 `start.bat`。它会自动完成：检查 Python → 清理 8000 端口 → 检查/安装依赖 → 启动后端 → 健康检查 → 打开浏览器。

> 若你的 Python 路径不同，编辑 `start.bat` 顶部的 `set "PYTHON=..."`。

**方式二：手动启动**

```bash
cd backend

# 1. 创建虚拟环境（首次）
python3.12 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate

# 2. 安装依赖
pip install -r requirements.txt
pip install bcrypt==4.0.1      # passlib 兼容需要

# 3. 启动服务
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

**方式三：Docker（未内置，可选）**

项目未提供 Dockerfile，如需容器化由团队自行补充。

## 3. 技术选型

### 3.1 后端

| 技术 | 版本 | 选型理由 |
|---|---|---|
| **FastAPI** | 0.115.0 | ① 自动生成 OpenAPI 文档（`/docs`），前后端联调零成本；② 原生 Pydantic 校验，请求体类型安全；③ 异步支持，后续接入 LLM 流式输出（SSE）无障碍 |
| **SQLAlchemy** | 2.0.35 | ① 2.0 风格 ORM，类型提示完善；② 声明式模型便于团队分工定义表结构；③ 未来可无痛切换 PostgreSQL（当前 SQLite） |
| **SQLite** | 内置 | ① 零配置，新人 clone 即可跑；② 单人/小团队开发足够；③ 通过 `DATABASE_URL` 可一行切换到 PostgreSQL |
| **Pydantic v2** | 2.9.2 | 请求体校验 + `pydantic-settings` 统一配置管理 |
| **python-jose** | 3.3.0 | JWT 签发/校验，无状态鉴权 |
| **passlib + bcrypt** | 1.7.4 / 4.0.1 | 密码哈希，bcrypt 是业界标准 |
| **sse-starlette** | 2.2.1 | SSE 流式响应，为 AI 答疑流式输出预留 |
| **uvicorn** | 0.30.6 | ASGI 服务器 |

**为什么不用 Django？** 项目是纯 API 服务 + 静态前端，不需要 Django 的 Admin/模板/ORM 全家桶，FastAPI 更轻且自带 API 文档。

### 3.2 前端

| 技术 | 选型理由 |
|---|---|
| **原生 HTML + ES5/ES6 JS** | ① 零构建步骤，改完刷新即生效，新人 0 门槛；② 无 node_modules 依赖地狱；③ 教学演示项目，可读性优先 |
| **ECharts 5**（`assets/js/vendor/echarts.min.js`） | ① 国内文档完善；② 热力图/雷达图/关系图开箱即用，本项目大量使用；③ 已本地化，不依赖 CDN |
| **原生 CSS + CSS 变量** | `assets/css/base.css` 定义设计令牌（`--brand-400`、`--lv-excellent` 等），换肤只需改变量 |
| **Hash 路由**（自研 30 行） | 无框架依赖，`#dashboard` 直接定位视图 |

**为什么不上 Vue/React？** 项目已用原生方案跑通全部 14 个页面，引入框架需重写且增加协作成本。**如团队一致要求可后续迁移，但需作为独立专项评估。**

### 3.3 测试

| 工具 | 文件 | 覆盖 |
|---|---|---|
| Python 标准库 `urllib` | `backend/regression_test.py` | 后端接口回归，**约 20 项** |
| Playwright（Node） | `e2e_smoke.js`（位于 `C:/tmp/pw/`） | 14 个页面冒烟 |

> **⚠️ E2E 测试脚本当前不在项目仓库内**，位于 `C:/tmp/pw/e2e_smoke.js`。建议第 4 周由数据/测试工程师迁入项目 `backend/tests/` 目录。

## 5. 核心架构约定（必读）

> 这一章是**全项目最重要的约定**，不理解会造成数据口径混乱。此前已因口径不统一修复过多个 Bug（详见交付报告第 23-34 章）。

### 5.1 统一响应信封

**后端所有接口必须返回统一格式**：

```python
# 成功
{"code": 0, "message": "success", "data": {...}, "traceId": "svc-xxxx"}

# 失败
{"code": -1, "message": "错误信息", "data": None, "traceId": "svc-xxxx"}
```

必须用 `app/schemas/common.py` 的工具函数：

```python
from ..schemas.common import ok, fail, list_response

return ok(data)                          # 成功
return ok(list_response(items, total))   # 列表 → {"total": N, "list": [...]}
return fail("班级不存在", 404)            # 失败
```

**关键点**：
- HTTP 状态码**始终 200**，业务错误通过 `code != 0` 表达（前端 `api.js` 依赖此约定）
- 唯一例外是真正的 404（静态资源）
- 全局异常处理器在 `main.py:41`，会兜底返回 `code=500`

### 5.2 鉴权机制

```
登录 POST /api/v1/auth/login  →  { token: "eyJ...", role: "student", ... }
                                    ↓
前端 localStorage.ca_session = { token: "Bearer eyJ...", role }
                                    ↓
后续请求 Header: Authorization: Bearer <JWT>
                                    ↓
后端 Depends(get_current_user) 解码 → user 对象（含 user_id, role）
```

**后端用法**：

```python
from ..middleware.auth import get_current_user

@router.get("/xxx")
def xxx(db: Session = Depends(get_db), user=Depends(get_current_user)):
    # user.user_id / user.role / user.name
    ...
```

**JWT 有效期**：7 天（`config.py: JWT_EXPIRE_MINUTES`）

**⚠️ 安全告警**：若未设置环境变量 `JWT_SECRET`，每次启动会生成随机密钥，控制台打印：
```
[SECURITY WARNING] JWT_SECRET 未通过环境变量设置...
```
**团队协作时必须统一 `JWT_SECRET`**，否则重启后所有人登录态失效。建议放 `.env`（`.env` 不入 Git，每人本地一份，值相同）。

### 5.3 前端路由与视图机制

**三步走**：

```
1. HTML 加容器     <section class="view" id="view-xxx"></section>
2. HTML 引脚本     <script src="assets/js/student/views/xxx.js"></script>
3. JS 末尾注册     Router.register('xxx', { title: '页面标题', mount: () => Xxx.render() });
```

**侧边栏菜单**加：
```html
<div class="nav-item" data-view="xxx">...</div>
```

**路由原理**（`common.js:267`，仅 30 行）：
- 监听 `.nav-item` 点击 + `hashchange`
- 切换 `.view` 的 `is-active` 类
- `cfg.mount()` **只在首次进入时执行一次**（`_mounted` 标记），后续进入走 `cfg.update()`
- 若页面需要每次进入都刷新数据，**必须实现 `update()` 方法**

### 5.4 ⭐ 两个核心数据口径（最重要）

这是本项目最容易出错的地方。全系统严格区分两个概念：

| 概念 | 英文 | 数据来源 | 当前可用性 | 展示位置 |
|---|---|---|---|---|
| **学习完成率** | completion / mastery | `learning_paths.mastery`（资源学习进度聚合） | ✅ 实时可用 | 学习路径、学情矩阵左列、热力图（默认）、驾驶舱指标 |
| **知识掌握率** | quizMastery | `answer_records` 答题正确率 | ⚠️ **题库未导入，全为 0** | 学情矩阵右列、热力图（切换）、练习模块 |

**计算函数**（`backend/app/routers/graph.py`）：

```python
_resource_mastery(user_id, db)      # 资源学习完成率：知识点下所有资源进度的平均值
_mastery_from_records(user_id, db)  # 答题正确率：answer_records 中 is_correct 的占比
_mastery_for_user(user_id, db)      # 当前 = _resource_mastery（题库导入后应改为两者取大）
_quiz_mastery_for_user(user_id, db) # 当前 = _mastery_from_records
```

**状态判定**（`_status_from_quiz_mastery`）：

```
资源学习完成率 ≥ 100%  →  done（已完成，绿色）
已答题（has_quiz=True）：
    ≥80%  →  done（已完成）
    ≥50%  →  doing（学习中）
    <50%  →  warn（待加强，含全错 0%）
未答题：
    资源进度 > 0%  →  doing（学习中）
    = 0%          →  todo（未开始）
```

**前端文案对照**：

| status | 前端显示 | 进度条颜色 |
|---|---|---|
| `done` | 已完成 | `excellent`（绿） |
| `doing` | 学习中 | `fair`（黄） |
| `warn` | 待加强 | `weak`（红） |
| `todo` | 未开始 | `none`（灰） |

> **📌 给 Agent 工程师的提示**：你接入 LLM 后，如果新增了"能力评估"类指标，**必须明确它属于上述哪个口径**，并在前端文案中区分，不要笼统称"掌握率"。

### 5.5 进度保存：不回退原则

`POST /api/v1/student/resources/{res_id}/progress` 采用**取最大值**策略：

```python
p.progress = max(prev_progress or 0, progress)
p.position = max(prev_position or 0, position)
```

**原因**：学生看完视频（100%）后重复播放，中途的 `timeupdate` 事件会带着低 position 上报，若直接覆盖会把 100% 重置。前端也有防御（`resource.js` 中已完成资源强制按 100% 上报）。

**⚠️ 新增任何进度上报逻辑时，必须遵守不回退原则。**

from pydantic import BaseModel
from typing import Optional

):
    """接口说明 —— 会出现在 /docs 中，务必写清楚"""
    # 1. 查询
    rows = db.query(...).filter(...).all()
    # 2. 组装（字段名用 camelCase，与前端一致）

#### 强制约定

| 约定 | 说明 |
|---|---|
| **响应信封** | 一律用 `ok()` / `fail()` / `list_response()`，禁止裸 `return {...}` |
| **字段命名** | 返回给前端的 JSON 字段用 **camelCase**（`kpId`、`avgMastery`）；数据库列用 snake_case（`kp_id`、`avg_mastery`） |
| **鉴权** | 除登录外所有接口必须 `user=Depends(get_current_user)` |
| **数据隔离** | 查询必须带 `user_id` 过滤，禁止返回他人数据 |
| **异常处理** | 业务错误用 `fail("原因", code)`，`code` 参考：404 不存在、403 无权限、400 参数错 |
| **除法保护** | 所有除法必须防零：`round(a / b, 1) if b else 0` |
| **注释** | 复杂算法必须写 docstring 说明口径；涉及"率"的计算必须注明分子分母 |
| **TODO 标记** | 待办用 `# TODO: 说明`，便于全局搜索 |

## 11. 红线与常见坑

### 11.1 🔴 绝对不能做的事

| 红线 | 原因 |
|---|---|
| **把 `api.js` 的 `config.mode` 改回 `'mock'`** | 前端会走 mock 数据，与后端脱节 |
| **接口返回不套 `ok()` / `fail()`** | 前端 `res.code !== 0` 判断失效，页面静默失败 |
| **改 `/ai/chat` 响应字段** | 前端 `chat.js` 已依赖 `content`/`citations`/`outOfScope` |
| **渲染用户输入不 `U.esc()`** | XSS 漏洞 |
| **硬编码颜色值** | 换肤失效、主题不一致 |
| **提交 `assets/resources/`（1.7GB）到 Git** | 仓库爆炸，所有人 clone 失败 |
| **把 API Key / JWT_SECRET 提交到 Git** | 安全泄露 |
| **直接改 `learning_paths.mastery` 而不走同步函数** | 数据不一致 |
| **删除 `regression_test.py` 中的用例来"让测试通过"** | 掩盖问题 |
| **未经通知改接口字段名** | 历史 Bug 根源 |

### 11.2 ⚠️ 常见坑（已踩过，别再踩）

| 坑 | 现象 | 规避 |
|---|---|---|
| **进度被 `min(99, ...)` 卡住** | PPT 看到最后一页只能到 99% | 所有百分比上限用 **100**，不用 99 |
| **进度回退** | 视频重复播放进度被重置 | 保存时 `max(历史值, 新值)` |
| **返回数组 vs `{list:[]}`** | 教师端班级下拉为空 | 前端 `Array.isArray(r) ? r : (r.list \|\| [])` |
| **HTML 引用已删除的 JS** | 页面加载慢/超时（404 等待） | 加 script 前确认文件存在 |
| **分母只算"有数据的"** | 指标虚高（83.3% 实际 3.7%） | 率的计算必须**含未开始的 0%** |
| **两个"掌握率"混淆** | 文案说学习完成率，数值是答题正确率 | 严格区分第 5.4 节两个口径 |
| **除法未防零** | `ZeroDivisionError` | `round(a/b, 1) if b else 0` |
| **前端改完不生效** | 浏览器缓存 | `Ctrl+Shift+R` 强刷（后端已加 NoCache） |
| **测试污染数据库** | 回归后数据异常 | 跑完测试清理 + 重新生成备份 |
| **`_mounted` 导致页面不刷新** | 二次进入视图数据不更新 | 实现 `update()` 方法 |

### 11.3 已知技术债（待治理）

| 债务 | 影响 | 建议 |
|---|---|---|
| `teacher.py` 1719 行 | 难维护、易冲突 | 拆为 `teacher.py` / `question.py` / `analysis.py`（P2，W4） |
| **无数据库迁移工具** | 改表结构要删库重建 | 引入 Alembic（P2，W5） |
| E2E 脚本在项目外 | 无法 CI、新人拿不到 | 迁入 `backend/tests/`（P5，W4） |
| `bcrypt` 未锁版本 | 新环境可能安装失败 | 写入 requirements.txt |
| 资源 1.7GB 未入 `.gitignore` | 仓库风险 | **立即处理**（P0，W1） |
| 部分接口有 N+1 查询 | 数据量增长后变慢 | 优化（P2，W3） |
| 前端无构建/无类型检查 | 大型改动易出错 | 可选引入 JSDoc / TS 检查 |
| 无 CI/CD | 人工测试 | GitHub Actions（P5，可选） |

### 12.5 排查技巧

| 问题 | 排查方法 |
|---|---|
| 页面白屏 | F12 Console 看 JS 错误；Network 看 404 |
| 接口返回异常 | 直接看 `/docs` 调接口；后端看控制台日志 |
| 数据不对 | 直接查库：`python3.12 -c "from app.database import SessionLocal; ..."` |
