# 多课程最小重构方案（步骤序列）

> 目标：让数据模型支持多课程，且**全程不破坏现有单课程功能**。
> 原则：只动"数据地基 + 课程上下文"，不重写任何业务引擎（图谱/答疑/出题/练习零改动）。
> 状态：待评审。评审通过后按步骤顺序执行，每步独立提交、独立可回滚。

---

## 〇、明确不做的事（最小化边界）

| 不做 | 理由 |
| --- | --- |
| 完整注册系统（自注册/邮箱验证） | 真实学校场景由教师/教务开账号；先做"教师建课 + 邀请码入课" |
| 班级实体改造 | 第一版"课程"即教学单元；`classes`/`teacher_classes` 保留不动，Phase 3 再议 |
| Alembic 迁移工具 | 沿用现有 `create_all + _migrate()` 手写机制；引入 Alembic 列入后续技术债清理 |
| 业务引擎改动 | 图谱渲染本就查库，知识点可增删后"实时更新"自动成立 |
| 拖拽式图谱画布 | 前后置关系第一版用多选下拉 |

## 一、核心决策（ADR-001）

```markdown
# ADR-001：课程上下文通过请求头 + FastAPI 依赖注入获取

## 状态
Proposed

## 背景
后端 102 处硬编码 C2026DS001（15 个文件），"学生-课程"关系在数据模型上不存在，
导致无法实现不同班级/课程的数据隔离。

## 备选方案
A. 每个接口显式加 courseId 参数 —— 语义最清晰，但 102 处签名改动 + 前端全部调用点改动
B. JWT 携带 activeCourseId —— 改动最小，但切换课程需重新签发 token，多标签页互相污染
C. 请求头 X-Course-Id + get_current_course_id() 依赖注入（选定）

## 决策
选 C。理由：
- 前端只在 api.js 的 request() 统一注入（一处改动），切课即改全局变量；
- 后端新增一个依赖函数，各路由把硬编码换成语柬参数，可逐文件渐进迁移，
  依赖函数带默认值 C2026DS001，未迁移的接口行为完全不变；
- 可逆性最好：删掉依赖与头注入即整体回滚。

## 后果
+ 渐进迁移、随时可停、老接口不受影响
+ 多标签页天然隔离（每个请求自带上下文）
- 少了显式参数的"自文档性"（用接口文档标注补偿）
- 需要做"用户是否属于该课程"的权限校验（依赖函数内完成）
```

## 二、数据模型（最小集）

```sql
-- 新表：用户-课程关联（教师授课 / 学生选课共用一张表）
CREATE TABLE user_courses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id   VARCHAR(64) NOT NULL,     -- → users.user_id
    course_id VARCHAR(32) NOT NULL,     -- → courses.course_id
    role_in_course VARCHAR(16) NOT NULL DEFAULT 'student',  -- teacher / student
    joined_at DATETIME,
    UNIQUE(user_id, course_id)
);

-- courses 表加列（走 _migrate）
ALTER TABLE courses ADD COLUMN invite_code VARCHAR(16) DEFAULT "";   -- 邀请码入课
ALTER TABLE courses ADD COLUMN owner_id  VARCHAR(64)  DEFAULT "";    -- 建课教师

-- 存量数据回填（关键！否则老用户"不在任何课程"，全站 403）
INSERT INTO user_courses (user_id, course_id, role_in_course, joined_at)
SELECT user_id, 'C2026DS001', role, CURRENT_TIMESTAMP FROM users;
```

> ⚠️ **回填是 Step 1 的必做部分**：没有它，权限校验一开就会把全体存量用户挡在门外。

## 四、竖切为什么选"资源中心"

1. 闭环最完整（列表 / 上传 / 删除 / 进度 / RAG 切片），一次验证所有机制；

### 存留风险（按优先级）
| # | 风险 | 影响 | 缓解/计划 |
| --- | --- | --- | --- |
| 1 | **旧学情模块仍走班级维度**（`state.classId='CL2301'` + dashboard/heatmap/analysis/intervention 等接口未接课程上下文） | 教师切换课程后，学情/热力图/干预/报告显示的还是演示快照，与所选课程无关，**易造成"隔离生效了但数据不对"的误解** | 短期：在这些页面加"演示数据"角标或文案说明；中期（Step 7 后）：这些接口迁到 `X-Course-Id`，数据从真实 answer_records 聚合 |
| 2 | **大量端点尚未接入课程上下文**（graph/quiz/ai/practice 等仍是 Query/body 默认值，头已被前端注入但后端未消费） | 学生切课后图谱/练习/AI 会话仍显示默认课数据；且任何人**手动传 courseId 可跨课程读数**（无成员校验的端点） | Step 7 逐模块迁移；AI 出题/答疑的 courseId 参数需与 X-Course-Id 对齐（二选一为准） |
| 3 | **成员校验覆盖不全** | 目前仅资源中心/dashboard/草稿发布走带校验依赖；其余端点无归属校验 | 随 Step 7 迁移逐个切换到带校验依赖；迁移完成前不对外暴露多租户语义 |
| 4 | **删除课程能力缺失** | 建课接口有了，没有删课/归档；误建课程无法清理 | Phase 3 补 `DELETE /teacher/courses/{id}`（连带 user_courses/资源目录/图谱清理，参考资源删除的三者一致模式） |
| 5 | **切课只刷新当前视图** | 其他视图数据在下一次进入时才刷新（mount 全量重绘，无脏数据），但如果未来引入局部缓存会踩坑 | 约定：视图数据一律 mount 时拉取，禁止跨视图缓存按 courseId 的数据 |
| 6 | **默认课程无邀请码**（seed 未生成） | 教师无法直接邀请学生进默认课 | 低成本：seed/建课时为默认课程补邀请码，或教师端"复制邀请码"入口 |
| 7 | **新教师无课程时的空态** | 切换器显示"暂无课程"，若教师直接访问资源页会 403（未加入任何课） | 空态引导已做（下拉文案+建课按钮）；403 提示文案已友好 |

### 结论
Step 6 完成后，**课程隔离的主链路（登录 → 归属 → 上下文 → 数据过滤）已端到端贯通**；存留风险集中在"未迁移模块仍读默认课程"的过渡期一致性，均已明确归属到 Step 7 / Phase 3，无阻塞性缺陷。
