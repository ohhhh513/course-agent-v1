> 对应代码：`backend/app/agent_st/`（agent/ 运行时与工具，rag/ 检索与校验）
> 流定义：`agent/flows/*.yaml` · 技能提示词：`agent/skills/*.md` · 编排：`agent/runtime.py`
> 更新日期：2026-09-07（出题 Agent 升级为 plan→validate→novelty 工作流后）

## 一、总览

| | 智能解析（explain） | 智能出题（generate_items） |
|---|---|---|
| 使用者 | 学生端「AI 智能答疑」 | 教师端「AI 智能出题」 |
| 入口 API | `POST /ai/chat`、`POST /ai/chat/stream` | `POST /question/gen`（`/gen/stream` 别名） |
| 工具集 | resolve_topic · retrieve_chunks · get_question | resolve_topic · retrieve_chunks · get_question · search_similar_questions · **submit_item_plan** · validate_question · **check_novelty** · save_question_draft |
| max_steps | 6 | 12 |
| 产物 | 讲解文本 + 溯源引用 citations | 结构化题目草稿（st_question_drafts） |

两种运行模式：

- **live 模式**（配置了 LLM_API_KEY）：LLM 按技能提示词自主编排工具调用（tool_calls 循环，受 max_steps 限制）；文本 delta 实时转发（工作线程 + 队列），`reasoning_content` 以 `think` 事件流出。
- **demo 模式**（未配 KEY）：`runtime._demo_turn` 按固定顺序调用工具，假流式输出。出题 demo 直接复制同章原题骨架（文案标明未走较大变动校验）。

## 二、智能解析流（explain）

### 输入
学生问题（**不要求带题号**）+ 会话 id + 可选 courseId/kpId。

### 执行步骤（live 模式由 LLM 按技能提示词编排）

1. `resolve_topic`：定位课程大章与王道小节；`uncertain=true` 时**仍用用户原话检索**，不拒绝作答
2. 有题号时 `get_question`（默认不带答案；用户明确要求核对才带）
3. `retrieve_chunks`：查询词 = 用户问题 + 小节名；source_types 默认 question_analysis / textbook / ppt（RAG 向量+关键词混合检索）
4. 组织回答（≤800 字）：
   - **一句话结论**
   - **依据**：关键断言后标 `[题号 {id}]` 或 `[小节 {section}]`，id 必须来自本轮工具结果
   - **【补充】**（可选）：证据不足时允许用课程常识补充，但必须显式声明「非课程原文」，禁止伪装成引用
   - **易错点**

### outOfScope 判定

不再"检索为空就整段覆盖成拒绝文案"。判定条件（`runtime._explain_out_of_scope`）：

**主题不确定（resolve_topic 未命中）+ 不像本课问题（无题号/章节/考点关键词）+ 检索最高分 < OFF_TOPIC_SCORE（默认 0.28，可在\backend\app\config.py中修改）**

三条同时成立才 `outOfScope=true`。生活类问题的混合检索也可能捞到几个大于等于0.12的低分切片，所以不能以"有命中"判相关，必须看最高分是否达到课程问题的水平；课程问题靠主题命中或关键词豁免，不受阈值影响。

配套提示词规则（skills/explain.md「越界问题」节，最高优先级）：与课程明显无关的问题**禁止讲解做法本身**（包括放进【补充】），直接简短说明助手只覆盖课程内容；【补充】机制仅适用于"课程相关但证据不足"的情形。

### 前端思考/工具面板顺序

流式期间面板按事件到达顺序维护条目：每个工具轮开始（tool_start）时结束所有未完成的 think 条目；`id="thinkLive"` 只赋给最后一个 live 思考条目（`toolsPanelHtml` 内计算 liveIdx），避免重复 id 导致新思考内容写进旧条目、顺序显示错乱。

### 前端事件

`meta(sessionId) → tool_start/tool_end → think(模型推理) → content(逐 token) → citations → done(outOfScope)`

## 三、智能出题流（generate_items）

### 输入三种模式（kpIds 与 exampleQuestionIds 之和必须 > 0，例题 0～3 道）

| 模式 | 行为 |
|---|---|
| 仅知识点 | 从零出题；`search_similar_questions` **只作防抄黑名单**，禁止当可微调骨架 |
| 仅例题 | `get_question(include_answer=true)` 读齐例题，按「较大变动」出新题，考点由例题章节推断 |
| 两者都有 | 考指定知识点；例题只作启发，新题必须相对例题足够不同 |

### 执行步骤

1. `resolve_topic`；若有 `example_question_ids` 则逐个 `get_question(include_answer=true)` 读例题全文
2. `retrieve_chunks`：取该小节教材/解析切片，约束考点表述（RAG 内容检索）
3. `search_similar_questions`：同章同图型题库题，**只作防抄黑名单**
4. `submit_item_plan`：提交构思——提问目标 / 实例草图 / **逐步解题过程与正确结论** / 干扰项易错点 / 相对对照题的变动说明（字段有最小长度校验，无 plan 不得出 JSON）
5. 按解题过程的易错点设计 3 个错误选项，输出闭集 JSON：
   `id(90001 起), chapter(王道小节前缀), question, options{A..D}, answer, analysis, has_image`，可选 `graph` / `options_graph`
6. `validate_question`：结构校验（章节闭集、选项完整、图类型闭集、端点一致、AOE 无环等）；失败按 errors 修改，最多再试 2 次
7. `check_novelty`：较大变动校验（见下）；失败必须加大变动重做，禁止数值微扰
8. 两项通过后 `save_question_draft` → `st_question_drafts` 表（按 user_id 归属），**不进 questions 正式题库**
9. 每保存一道题即推送 `draft` 事件（教师端流式预览）

### 「较大变动」校验规则（rag/novelty.py）

| 维度 | 通过条件（满足其一即 sufficient） | 判定为偷懒（trivial） |
|---|---|---|
| 题干 | 归一化相似度 < 0.65，或提问目标不同（ASK_MARKERS 标记集） | 相似度 ≥ 0.85 且提问目标相同 |
| 图 | 边集 Jaccard < 0.6，或结点数差 ≥ 2，或**非平移式**边权实质改动 ≥ 3 处 | 同型同规模、边集 Jaccard ≥ 0.8、边权改动 ≤ 2 处或整体平移 |

- 平移检测：所有共享边权变化量完全一致（如全部 +1）视为零变动
- 例：`1,3,6 选最大 → 1,2,6 选最大`（微扰）✗；`问第一条边 → 问总权值`（换提问目标）✓；多条边权非平移改动 ✓
- 改完必须**重算答案**，禁止沿用源题答案
- 无对照题时仅做自洽检查

### 落库与发布链路

```
草稿（st_question_drafts，user_id 隔离）
  → 草稿箱（GET/PUT/DELETE /question/drafts*，编辑保存即重新 validate）
  → 发布（POST /question/drafts/{id}/publish：再校验 → AI 前缀自增题号
     → kp 按 kp_section_mapping.json 小节映射（首项为主，kp_path 多级）
     → figure_json 转换 → status=published 入 questions 正式题库）
```

## 五、SSE 事件协议

| 事件 | 载荷 | 说明 |
|---|---|---|
| `meta` | `{sessionId or batchId, count?}` | 会话/批次开始 |
| `tool_start` / `tool_end` | `{name, args}` / `{name, ok, preview}` | 工具调用（前端折叠面板） |
| `think` | `{delta}` | 模型内部推理（reasoning_content，仅答疑流） |
| `content` | `{delta}` | 回答正文逐 token（仅答疑流） |
| `log` | `{type, delta?}` | 出题过程文本（仅出题流） |
| `draft` | `{draft_id, status, errors, payload}` | 每题落库即推（仅出题流） |
| `citations` | `{items[]}` | 溯源引用 |
| `error` | `{message}` | 错误（单题失败不中断整批） |
| `done` | `{outOfScope, demo, drafts / batchId, draftIds, count}` | 结束 |
