# 智能体入门与 AI 协作手册（给不懂智能体的队友）

> 谁该读：接手这个项目、但对「智能体（Agent）」不熟的队友 —— **以及你正在用的那个 AI 助手**。
> 读完你会得到什么：知道智能体是怎么跑起来的、为什么不能随心所欲地命令 AI 改这个项目、以及一套「怎么指挥它」的固定话术。
> 配套：`AGENTS.md`（给 AI 看的硬规矩）、`docs/Agent化改造-交接与阶段划分.md`（任务与阶段）。

## 第一部分 · 智能体到底是什么

### 1.1 一句话讲完

**大模型只会「说话」；工具让它「能做事」；循环让它「能连着做几件事」。** 三者加起来才叫智能体。

普通聊天机器人：你问「我有哪些预警？」，它只能编一个答案给你。
这个项目里的智能体：它会**真的去数据库查**你的预警，然后把查到的结果讲给你听 —— 之所以能查，是因为我们给了它一把「工具」。

### 1.2 四个零件

| 零件 | 干什么 | 没有它会怎样 |
| --- | --- | --- |
| **大脑（大模型 / LLM）** | 负责「想」和「说」：读懂问题、决定要不要用工具、组织回答 | 没有它 = 演示模式，只能按固定套路回话 |
| **手（工具 / tool）** | 负责「做」：查预警、查正确率、检索资料、保存草稿 | 没有工具 = 只能说漂亮话，数字全靠编 |
| **资料（上下文 / context）** | 每一轮都要**重新**告诉它的东西：它是什么角色、用户是谁、哪门课、最近聊了什么 | 没有上下文 = 答非所问、跨课程串数据 |
| **循环（loop）** | 「想 → 调工具 → 看结果 → 再想 → 最后回答」，有步数上限 | 没有循环 = 只能一问一答，做不了多步骤的事 |

关键点：**大模型不记得任何事，也没有任何权限。** 它每轮看到的、能做的，全是我们这一轮递给它的。所以「它能看到什么、能做什么」是一件**由我们（代码）决定**的事，不是它自己决定的。

### 1.3 一个好用的比喻：新来的实习生

把大模型当成一个**非常聪明、但完全不了解你系统的实习生**：

- 他表达能力很强，你问什么他都能说，**包括他不知道的事**（这就是「幻觉」）。
- 你得给他一份**工作手册**（= 我们项目里的 `skills/*.md`），告诉他这类问题该怎么答、什么不许说。
- 你得给他一串**钥匙**（= 工具注册表），他手里没有的钥匙，他开不了门 —— 也正因为这样，**给学生用的智能体不可能拿到「出题」的钥匙**。
- 你每次找他办事，都要把**当前情况**再说一遍（= 上下文）：这是谁、哪门课、上次聊到哪。
- 他一次任务最多允许尝试几步（= `max_steps`），避免他反复绕圈子。

### 1.4 对应到本项目的文件

| 零件 | 本项目里叫什么 | 在哪 |
| --- | --- | --- |
| 大脑 | LLM（DeepSeek 兼容端点） | `backend/app/agent_st/net.py`、`agent/llm.py` |
| 手 | 工具注册表 | `backend/app/agent_st/agent/registry.py` + `tools/*.py` |
| 工作手册 | 技能（skill，行为规范） | `backend/app/agent_st/agent/skills/*.md` |
| 任务单 | 任务流（flow） | `backend/app/agent_st/agent/flows/*.yaml` |
| 人物设定 | 人格（persona） | `backend/app/agent_st/agent/personas/course_tutor.yaml` |
| 循环 | 运行层（runtime / sdk_runner） | `agent/runtime.py`、`agent/sdk_runner.py` |

## 第二部分 · 这个项目的智能体是怎么跑的

### 2.1 三层配置：能做什么 / 这条流程给什么 / 怎么说话

这三层分得很清楚，改东西时要找对层，别改错地方：

| 层 | 文件 | 回答什么问题 | 举例子 |
| --- | --- | --- | --- |
| **注册表** | `registry.py` + `tools/*.py` | 系统里一共有哪些工具、每个工具要什么参数、**哪些角色能用** | 「`my_alerts` 这个工具谁都能用；`save_question_draft` 只有教师/管理员能用」 |
| **任务流** | `flows/*.yaml` | 这条流程**允许用哪些工具**、**最多几步**、**谁能用这条流** | 「答疑流最多 6 步、三端可用；出题流最多 12 步、只允许教师」 |
| **技能** | `skills/*.md` | 这类问题**该怎么答**：先给结论还是先给依据、什么不许说、口径怎么解释 | 「学情类问题禁止估算；回答必须自包含，不许写『见上文』」 |

一句话记忆：**注册表 = 有哪些工具；任务流 = 这次给哪几件；技能 = 怎么用它们说话。**

### 2.2 两条运行层：legacy 和 sdk

项目里有**两套实现**，做同一件事，产出的东西完全一样：

| | `runtime.py`（legacy） | `sdk_runner.py`（sdk） |
| --- | --- | --- |
| 是什么 | 我们自己手写的「模型 ⇄ 工具」循环 | 用 OpenAI Agents SDK（`Agent` + `Runner.run_streamed`）跑同一批工具 |
| 为什么要它 | 不依赖第三方包，环境不齐也能跑 | 这是「框架规范做法」，后面加审批、MCP 都靠它 |
| 怎么切换 | `AGENT_RUNTIME=legacy`（默认） | `AGENT_RUNTIME=sdk`；没装包或没配 key 会自动回退 legacy |

**最重要的规矩：两套运行层的事件名和字段必须一模一样**（见 2.4）。这就是为什么换运行层、换模型，前端一行都不用改。

### 2.3 一次提问的完整旅程（真实轨迹）

场景：学生在「AI 智能答疑」里打了一句 **「我有哪些预警？」**

1. **浏览器**：`chat.js` 发一个 SSE 请求 `POST /api/v1/ai/chat/stream`，带上登录令牌和当前课程（`X-Course-Id`）。
2. **后端入口**：`routers/ai.py` 校验登录、校验课程成员身份，组装上下文：`{ courseId: 当前课程, role: student }`。
   - `role` 是**服务端按登录用户填的**，模型改不了 —— 所以它冒充不了教师。
3. **运行层**：`runtime.run_turn()` 先看任务流 `explain.yaml` 声明的 `roles`，确认这个角色能用；然后建会话（`chat_sessions`）、把用户这句话存进 `chat_messages`。
4. **拼系统提示**：人格 + 任务流说明 + 技能手册（`explain.md`）+ 本课程的章节/知识点目录 + 最近 12 条历史消息。
5. **第一次问模型**：模型看完资料，决定「我需要先查数据」，回一个工具调用请求：`my_alerts()`。
6. **执行工具**：`registry.execute()` 先做两次校验（这条流允许它吗？这个角色允许它吗？），然后真的去 SQLite 查预警表 —— **按当前用户 + 当前课程**过滤。
7. **把结果还给模型**：模型看到真实的预警清单（比如 KP014 二叉树遍历 50% 黄灯），再决定要不要接着查（比如 `weak_ranking` 排个「最该先补」）。
8. **边想边发**：整个过程实时吐给前端 —— 工具开始/结束、模型的思考（`think`）、正文逐字（`content`）、引用（`citations`）、建议按钮（`action`）、结束（`done`）。
9. **落库**：回答写进 `chat_messages`，本轮调用了哪些工具写进同一行的 `tool_log` 字段。
10. **前端渲染**：正文显示了，末尾还有两个按钮 —— 按钮只是**建议**，学生点了才会跳转（跳转范围由白名单控制）。

用一张图看这个循环：

```text
用户提问
   │
   ▼
[后端] 组装上下文（who / which course / role / 历史）
   │
   ▼
[模型] 想 ──► 要不要用工具？ ──► 要 ──► [注册表] 校验 flow+角色 ──► 执行工具 ──► 查库
   ▲                                        │
   └──────────── 把工具结果还给它 ◄──────────┘
   │
   └──► 不用了 ──► 写回答 ──► 事件流回前端（逐字）──► 落库
```

### 2.4 事件契约：前端和运行层之间唯一的约定

不管哪套运行层，吐出来的事件就那么几种，前端只认它们：

`session` → `tool_start` / `tool_end` → `think` → `text`（逐字正文）→ `citations` → `action` → `error`（如果有）→ `done`

完整对照表见交接文档第 3 节。**改运行层不许改事件名和字段** —— 这是最容易把前端搞崩的地方。

### 2.5 数据落在哪（为什么我们敢说「不改数据库」）

| 数据 | 落在哪张表 | 说明 |
| --- | --- | --- |
| 会话 | `chat_sessions` | 按 `user_id + course_id` 分开 |
| 消息 | `chat_messages` | `tool_log` 列存本轮工具调用（JSON 文本） |
| 出题草稿 | `st_question_drafts` | 只进草稿，不进正式题库 |
| 预警 | `alerts` | 已按课程落库 |
| 答题记录 | `answer_records` | 正确率、薄弱点、预警的共同来源 |

要存新东西时，**先在这张表里找现成的列**（比如「待审批动作」就放 `chat_messages.tool_log`），而不是加列加表。

### 2.6 演示模式和真实模式

- 配了 `LLM_API_KEY` → **live**：模型真的在思考、挑工具、组织回答。
- 没配 → **demo**：`runtime._demo_turn` 按固定顺序调工具，输出一段模板化的回答（真实检索、但没生成）。

所以「怎么感觉回答很死板」的第一个排查方向，不是代码坏了，而是**有没有配 key**。

## 第三部分 · 为什么不能随心所欲地命令 AI 改这个项目

AI 助手不是「更快的程序员」，它更像**一个不认识你系统、但非常自信的实习生**。下面这些事故，都是「随口一句话」造成的典型后果：

| # | 常见命令 | 会发生什么 | 后果 | 正确做法 |
| --- | --- | --- | --- | --- |
| 1 | 「帮我把学情统计改准确点」 | 它不认识你的口径，自己发明一套算法 | 数字全变，还说不清哪个对 | 先让它读文档、说出现在的口径，再讨论改什么 |
| 2 | 「这个功能没用了，删掉」 | 它顺手删了别人还在用的接口/字段 | 教师端或学生端白屏 | 先问「谁在调用」，再动手 |
| 3 | 「帮我加个字段存一下」 | 它改了数据库结构 | 别人电脑上的旧库打不开，部署失败 | **绝对禁止**，用现有列或 JSON 列 |
| 4 | 「回答太短，改长一点」 | 它改了运行层的事件名 | 前端一个事件都收不到 | 提示词问题只改 `skills/*.md` |
| 5 | 「这块代码太乱，重构一下」 | 它大范围重写，一次提交几十个文件 | 出错了不知道哪一步坏的，回滚都难 | 一次一件事，重构单独排期 |
| 6 | 「应该没问题吧，先提交」 | 它没跑验证就提交 | 上线即坏 | 要求它给出**命令输出**作为证据 |
| 7 | 「拿这个学生数据试试」 | 它在真实库上做实验 | 演示数据被污染，别人看到假数据 | 所有验证都在**库副本**上做 |
| 8 | 「顺便把另一件事也做了」 | 它一次改两件事 | 两件事都说不清谁对谁错 | 一次只做一件，做完再下一件 |

### 「看起来对」的陷阱

AI 最容易犯的不是报错，而是**不报错的错**：

- 它编一个看起来很合理的知识点编号（实际库里没有）→ 界面显示 0，没人知道是错的。
- 它把上下文里的 `courseId` 忘了传 → 检索变成「全库混搜」，答案看起来还挺像那么回事。
- 它把「正确率」算成了另一种口径 → 数字自洽、但和预警口径对不上。

所以每个阶段都要有**明确的验收标准**（交接文档第 5 节里都写好了），并且要求它拿出证据。

## 第四部分 · 怎么指挥 AI（黄金四步 + 模板）

### 4.1 黄金四步

1. **先让它读**：把 `AGENTS.md` + 交接文档 + 待修复清单丢给它，要它用「5 行汇报」复述任务边界。
2. **要计划，不要直接改**：让它先说「打算改哪些文件、影响什么、怎么验证」，**等你说「开始」再动手**。
3. **一次一件事**：批准一个阶段，做完、验证、提交，再开下一个。
4. **要证据**：命令输出、事件序列、点了几次看到什么 —— 没有证据不算完成。

### 4.2 复制即用的提示词

**开工（每个新任务都先发这个）**

```text
请先在仓库里读这四份文件，不要改任何代码：
1) AGENTS.md
2) docs/Agent化改造-交接与阶段划分.md
3) docs/智能体入门与AI协作手册.md
4) 待修复清单.md

然后用这 5 行回答我，等我确认后再动手：
【在做什么】…
【为什么】…
【影响面】前端/后端/数据库，具体文件和接口
【怎么验证】跑哪条命令、看到什么算过
【下一步】…
```

**收工（每次都要）**

```text
请用这 5 行汇报结果，并贴出验证证据（命令输出 / 事件序列 / 页面截图说明）：
【在做什么】…
【为什么】…
【影响面】…（实际改了哪些文件）
【怎么验证】…（你跑了什么，结果是什么）
【下一步】…（我该做什么、还有什么风险）
```

**修 bug（防止它乱改）**

```text
先只做诊断，不要改代码：
1) 复现/定位这个 bug 在哪一层（前端/后端/数据）
2) 说清现在的行为、期望的行为、可能的原因
3) 给修复方案和影响面，等我确认后再改
```

**它想改数据库时**

```text
停。本项目不允许改数据库格式（不加表、不加列、不改字段类型）。
请改用现有列（chat_messages.tool_log / reports.detail_json 等）重新给方案。
```

### 4.3 你要检查什么（人类版清单）

- [ ] 它有没有先读文档、先复述边界？（上来就改代码 = 立刻喊停）
- [ ] 后端改动前有没有给影响分析？学生端/教师端分别会怎样？
- [ ] 有没有碰数据库结构？（碰了就是红线）
- [ ] 有没有改事件名/字段？（改了前端就得跟着改）
- [ ] 有没有验证证据？（「应该没问题」不算）
- [ ] 一次是不是只做了一件事？（一次提交里混了多个阶段要拆开）
- [ ] 它有没有说「下一步该做什么」？没有就追问。

## 第五部分 · 常见问题与术语表

### 5.1 常见问题

**Q：为什么模型「看不到的工具就调不到」？**
A：工具清单是我们主动递给它的。清单里没有，它根本不知道有这么个工具；就算它硬编一个名字，执行前还有第二道角色校验会拦下。

**Q：为什么学生的智能体不能出题？**
A：出题会写草稿表，属于写操作；而且教师才有出题权限。任务流 `generate_items.yaml` 只允许教师/管理员，工具本身也标记了角色 —— 两道门。

**Q：为什么回答里必须带结论和数字，不能只说「你去某某页面看看」？**
A：因为用户要的是答案。只给按钮等于把活推回给人。这条写进了技能手册，属于行为规范问题，改 `skills/explain.md` 而不是改代码。

**Q：为什么它有时候回答得慢？**
A：它可能要连续调用好几个工具（查预警 → 排薄弱点 → 再解释口径），每次都要等模型返回。有 `max_steps` 上限，不会无限循环。

**Q：我能直接让 AI 帮我改这个项目的代码吗？**
A：可以，但**必须**按第四部分的方式指挥。最危险的不是它写错代码，而是它写的东西「看起来对」。

### 5.2 术语表

| 词 | 人话解释 |
| --- | --- |
| LLM / 大模型 | 负责「想」和「说」的大脑，不认识你的系统 |
| Token | 模型处理文字的最小单位，也是计费单位 |
| 工具 / tool | 给模型装的手：查数据、写草稿、检索资料 |
| 工具注册表 / registry | 系统里所有工具的清单 + 参数定义 + **谁能用** |
| 任务流 / flow | 一条业务流程：给哪些工具、最多几步、谁能用 |
| 技能 / skill | 行为手册：这类问题怎么答、什么不许说 |
| 上下文 / context | 这一轮递给模型的全部资料（身份、课程、历史） |
| 运行层 / runtime | 负责「想 → 调工具 → 再想」这个循环的代码 |
| 事件契约 | 运行层发给前端的事件名与字段，改了前端就崩 |
| SSE / 流式 | 一边生成一边推给浏览器，所以能逐字显示 |
| 幻觉 | 模型一本正经地编造不存在的事实、接口或编号 |
| MCP | 一种标准协议，让外部客户端（Claude Desktop 等）也能用我们的工具 |
| 审批闸门 | 写操作先「待批准」，用户点确认才真正执行 |

## 第六部分 · 这个仓库特有的坑

- **前端可能是旧版**：静态资源已设 no-cache，但浏览器仍可能缓存。症状是「后端明明产出了新东西，页面没反应」→ 先硬刷新（Ctrl+F5）。
- **PowerShell 提交中文**：提交信息里含 ASCII 双引号（`"`）会被吃掉，用 `「」`。
- **代理**：之前 VPN 代理污染过出网请求，现在统一走标准环境变量；出网失败先看 `net.py` 与系统代理设置。
- **验证用库副本**：`backend/app/data/course_agent.db` 是演示库，别直接改；`dev_tools/` 里的脚本默认自带副本。
- **`backend/data.zip`**：打包给别人用的产物，别删、别误提交（当前有意保持未跟踪）。
- **演示账号**：管理员 `admin/admin`；教师 `wangjg/123456`；学生 `stu01…stu10/123456`；课程 `CCHYJTKE`。

## 最后一句话

你不需要懂代码，但你需要**每次都要求 AI 说清楚三件事：现在在干什么、会影响什么、下一步做什么**。
它说得清楚，你才敢放它改；它说不清楚，就先别让它动手。
