## 1. 项目概述

### 1.1 一句话定位

面向《数据结构》课程的 **AI 驱动教学辅助系统**：为学生提供个性化学习路径、资源学习、智能练习与 AI 答疑；为教师提供班级学情监测、薄弱点归因、教学干预与 AI 出题。

### 1.2 两端功能全景

**学生端（7 个视图）**

| 路由 key | 页面 | 核心能力 |
|---|---|---|
| `dashboard` | 学习驾驶舱 | 核心指标、今日任务、学习路径概览 |
| `graph` | 课程图谱导航 | 知识/问题/目标三图谱可视化、知识点详情、前置关系 |
| `resource` | 学习资源中心 | 学习路径 + 资源卡片、视频/PPT/PDF 播放与进度 |
| `ai` | AI 智能答疑 | 多教学法对话、引用溯源（**待 AI 接入**） |
| `practice` | 智能练习 | 练习模式、答题判分、错题本 |
| `mastery` | 我的学情 | 知识点矩阵、能力雷达、成长轨迹、班级对比 |
| `alerts` | 预警与提醒中心 | 学习预警、教师私信、系统通知 |

**教师端（7 个视图）**

| 路由 key | 页面 | 核心能力 |
|---|---|---|
| `dashboard` | 教学驾驶舱 | 班级总览、薄弱知识点排行、待办 |
| `monitor` | 学情监测看板 | 热力图（完成率/掌握率切换）、学生个体详情、预警复核 |
| `analysis` | 归因与错题分析 | 错题分布、薄弱关系链、AI 归因建议 |
| `question` | AI 出题与题库管理 | 题库 CRUD、AI 生成习题（**待 AI 接入**） |
| `intervention` | 教学干预与策略 | 干预策略生成、执行跟踪、效果复测 |
| `report` | 学情分析报告 | 报告生成与导出 |
| `resource` | 资源管理 | 资源上传、知识点挂靠 |

### 1.3 当前完成度与已知缺口（交接时真实状态）

| 模块 | 状态 | 说明 |
|---|---|---|
| 非 AI 业务接口 | ✅ 全部真实可用 | 数据从关系表实时计算，无 mock |
| 学生端 / 教师端页面 | ✅ 完成 | 14 个页面功能闭环 |
| 课程资源 | ✅ 9 章 65 个 | 视频/PPT/教材（见 `assets/resources/`，**1.7GB 不入 Git**） |
| 知识图谱 | ✅ 9 章 34 知识点 | 含前置关系 |
| **AI 智能答疑** | ⚠️ mock 兜底 | 关键词匹配预设答案（`backend/app/routers/ai.py` 的 `_ANSWER_BANK`），待接 LLM + RAG |
| **AI 出题** | ⚠️ 题库筛选 | 从现有题库随机抽题，非真正生成 |
| **题库** | 🔴 严重不足 | 仅十余道，覆盖 34 个知识点远远不够 |
| 答题记录 / 学情 | 🔴 近乎为空 | 全库答题记录极少，导致"知识掌握率"多为 0 |

> **⚠️ 交接第一要务**：团队两大缺口 = **① AI 能力未接入**（P1 负责）；**② 题库与学情数据严重不足**（需专人扩充 + 造数据）。这两点直接决定 `§7` 的分工与排期。

## 2. 快速上手

### 2.1 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Python | **3.11**（推荐） | 后端运行时（FastAPI 要求） |
| Node.js | 18+ | **仅跑 E2E 测试需要**；前端是静态文件，无需构建 |
| 浏览器 | Chrome / Edge | 前端无构建，直接打开 |
| 系统 | Windows / macOS / Linux | 注意路径跨平台 |

### 2.2 三步启动

**方式一 · 一键启动（Windows，推荐）**

双击根目录 `start.bat`。它会：检查 Python → 清理 8000 端口 → 装依赖 → 起后端 → 健康检查 → 开浏览器。

> 注意：`start.bat` 已改为自动探测本机 Python 3.11（`python3.11` → `py -3.11` → PATH 中的 `python`，要求 3.11.x），无需再手动修改脚本内的解释器路径。

**方式二 · 手动启动（跨平台）**

```bash
cd backend

# 1. 虚拟环境（首次）
python3.11 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate

# 2. 装依赖
pip install -r requirements.txt
pip install bcrypt==4.0.1            # passlib 兼容需要，必须锁版本

# 3. 起服务
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

> **`.env` 必须本地创建**（仓库不提交）：`cp .env.example .env`，并把 `JWT_SECRET` 改成团队统一值（见 `§6.6` 红线）。

**方式三 · Docker**：项目未内置 Dockerfile，需容器化由团队自行补充。

## 3. 技术选型

### 3.1 后端

| 技术 | 版本 | 选型理由 |
|---|---|---|
| **FastAPI** | 0.115.0 | ① 自动 OpenAPI（`/docs`），前后端联调零成本；② 原生 Pydantic 校验；③ 异步原生，后续接 LLM 流式（SSE）无障碍 |
| **SQLAlchemy** | 2.0.35 | ① 2.0 声明式 ORM，类型提示完善；② 表结构清晰便于分工；③ 一行切 PostgreSQL（当前 SQLite） |
| **SQLite** | 内置 | ① 零配置，clone 即跑；② 小团队开发足够；③ `DATABASE_URL` 可切 PG |
| **Pydantic v2** | 2.9.2 | 请求校验 + `pydantic-settings` 配置管理 |
| **python-jose** | 3.3.0 | JWT 签发/校验，无状态鉴权 |
| **passlib + bcrypt** | 1.7.4 / 4.0.1 | 密码哈希（bcrypt 业界标准，锁 4.0.1 防装失败） |
| **sse-starlette** | 2.2.1 | SSE 流式响应，为 AI 流式答疑预留 |
| **uvicorn** | 0.30.6 | ASGI 服务器 |

**为什么不用 Django？** 纯 API + 静态前端，不需要 Admin/模板/ORM 全家桶，FastAPI 更轻且自带文档。

### 3.2 前端

| 技术 | 选型理由 |
|---|---|
| **原生 HTML + ES6 JS** | ① 零构建，改完刷新即生效，新人 0 门槛；② 无 node_modules 依赖地狱；③ 教学演示可读性优先 |
| **ECharts 5**（`assets/js/vendor/echarts.min.js`） | ① 国内文档全；② 热力/雷达/关系图开箱即用；③ 已本地化，不依赖 CDN |
| **原生 CSS + CSS 变量** | `base.css` 定义设计令牌，换肤只改变量 |
| **Hash 路由**（自研） | 无框架依赖，`#dashboard` 直接定位视图 |

**为什么不上 Vue/React？** 已用原生方案跑通全部 14 页。引框架需重写且增加协作成本。**如团队一致要求可后续迁移，但须作为独立专项评估。**

### 3.3 测试

| 工具 | 文件 | 覆盖 |
|---|---|---|
| Python `urllib` | `backend/regression_test.py` | 后端接口回归，**约 20 项** |
| Playwright（Node） | `C:/tmp/pw/e2e_smoke.js`（**当前不在仓库内**） | 14 页冒烟 |

## 5. 核心架构约定（必读）

1. **统一响应信封**：所有接口返回 `{ code, message, data, traceId }`，成功 `code=0`，前端只读 `data`。来源 `app/schemas/common.py`，**禁止各路由自行拼格式**。
2. **路由前缀**：全部 `/api/v1/...`；列表类接口统一返回 `{ total, list }`。
3. **mock/http 切换**：前端所有取数走 `API.*`；`api.js` 已置 `http` 直连后端，**页面零改动对接**（详见 `docs/前端架构与运行.md` §5）。
4. **鉴权**：`Authorization: Bearer <JWT>`；`/auth/login` 签发，`get_current_user` 解析 userId/role。失效返回 `401` + 信封。
5. **前端全局脚本加载顺序**：`vendor/echarts → common → charts → api → auth → 业务( student/teacher )`，新增脚本须遵循依赖链。
6. **数据字段强依赖**：前端按 `docs/数据模型与Mock说明.md` §3 的字段路径读取，后端返回结构必须对齐，缺失会页面异常。

## 6. 开发规范

### 6.1 命名

```
视图对象 PascalCase   Dashboard、ResourceView
方法     camelCase    loadHeat、updateLabels
CSS 类   kebab-case   .res-card、.list__item--clickable
DOM id   camelCase    #heatChart、#weakChips
常量     UPPER_SNAKE  CHAPTER_NAMES、STATUS_MAP
后端表   snake_case 复数   learning_paths、answer_records
后端列   snake_case        user_id、created_at
```

### 6.2 接口规范

- 一律走 `ok()/fail()/list_response()`，不手写字典。
- 业务异常用中文 `message`，前端直接 `Toast` 展示。
- 列表返回 `{ total, list }`；分页参数 `page`/`size`。
- 改接口必须同步更新 `docs/接口文档.md` 与本文档。

### 6.3 数据库规范

| 约定 | 说明 |
|---|---|
| 主键 | 业务主键用字符串（`KP01`/`R048`/`S20260317`），自增用 `id` |
| 时间 | `datetime`，UTC（`datetime.utcnow()`） |
| JSON 字段 | 存文本，用 `app/utils.py` 的 `loads()/dumps()` |
| 外键 | SQLite 已开 PRAGMA，但**建议业务层保一致**，不依赖级联 |
| 迁移 | **当前无 Alembic**（已知技术债）。改表结构：① 改 model → ② 删库重启自动 seed，或写迁移脚本 |

### 6.4 测试规范（提交前必跑）

```bash
cd backend
python3.11 regression_test.py
# 期望：终端输出 ALL PASS，passed ≈ total（约 20 项）
```

- 新增接口**必须**补用例；测试会真实读写库，跑完清理测试数据并重新生成备份。
- E2E：`node C:/tmp/pw/e2e_smoke.js`（迁仓后 `backend/tests/e2e_smoke.js`）。

**提交前自检清单**：
- [ ] 后端回归 全绿 PASS（约 20 项）；E2E 无 FAIL；无新增 JS 控制台错误
- [ ] 测试数据已清理
- [ ] 改表结构 → 同步 `seed/mock_data.py`
- [ ] 改接口 → 已更新 `docs/` 描述 + 本文档

### 6.5 Git 规范（建议采用）

**分支模型（简化 Git Flow）**
```
main        生产基线，只从 develop 合并，禁止直 push
develop     集成分支，日常合并
feature/*   功能分支：feature/ai-rag、feature/question-bank
fix/*       修复分支：fix/heatmap-tooltip
```

**提交信息（Conventional Commits）**
```
<type>(<scope>): <subject>
type:  feat | fix | docs | style | refactor | test | chore
scope: ai | student | teacher | practice | graph | api | ui | db
例：feat(ai): 接入通义千问实现 /ai/chat 流式答疑
```

**PR 要求**：至少 1 人 Review（架构师必看）；描述改了什么/为什么/如何验证；附回归结果；**接口变更必须同步文档**。

### 6.6 红线（违反即回滚）

| ❌ 禁止 | 后果 |
|---|---|
| 提交 `assets/resources/`（1.7GB）到 Git | 仓库爆炸，全员 clone 失败（已 gitignore） |
| 把 API Key / `JWT_SECRET` 提交到 Git | 安全泄露 |
| 改 `api.js` 的 `mode` 回 `mock` | 前端脱离真实后端 |
| 硬编码图表颜色（应取 CSS 变量） | 换肤失效 |
| 渲染用户输入不用 `U.esc()` | XSS |
| 各路由自造响应格式 | 破坏前端解析 |

> **JWT_SECRET 协作铁律**：每位成员本地 `.env` 的 `JWT_SECRET` 必须**完全一致**（用同一随机串），否则一人重启服务后其他人登录态全失效。生成：`python -c "import secrets; print(secrets.token_hex(32))"`。
