# 联网题目去重与连续换题：影响与实现方案

状态：用户已确认并实施完成。历史/比较、完整工具循环、并发、权限与回退检查通过；独立空历史教师的库副本中真实连续提问两次，获得两道不同带图题。原教师历史完整保留，也验证了跳过旧题及来源不足时不重复发送。

## 现象与原因

- 任课教师近期题卡记录中，同一道循环队列元素个数题出现四次；标题、题号前缀和排版存在差别。
- `AgentStore.history()` 只返回消息正文，不返回 `tool_log` 中的实际题卡。模型看到的是「已整理一道题」等总结，无法可靠知道上一题的内容。
- `prepare_web_question` 校验来源、题面与配图，但不比较已发送题卡；每次新建 UUID 只是不同卡片 ID，不能代表不同题目。
- 相同公开搜索通常会再次出现靠前来源；PDF 候选按固定规则排序，缺少去重时容易再次选择同一题。PDF 原文缓存用于复用读取结果，本身不记录选过哪题，清缓存不能解决此问题。

## 本轮行为

1. **默认找新题**：老师继续说「找一道」「再来一道」「换一道」，以及重复提交相同找题请求时，优先排除已发送题目。同一轮也不重复发送相同题目。
2. **教师与课程隔离**：复用已有会话和消息 JSON，读取当前教师、当前课程近 30 天最近 200 条含题卡的消息；新建会话也能避开近期发过的题。其他教师、课程、学生和管理员不纳入该历史范围，不将个人历史发给公开搜索服务。
3. **题目级识别**：比较规范化题干、选项、来源中的原题位置与配图关联，兼容旧题卡；忽略卡片标题、UUID、题号前缀、空白与排版差异。题目数字、条件、选项及实际配图差异仍需保留判断，不能把同知识点的不同题一概拦掉。明显相同的文字题跨来源也应识别，依赖不同图形的题不只凭短题干判重复。
4. **先排除、再兜底校验**：把已发过题目的必要摘要提供给当前教师选题链路，PDF 候选优先显示未用题；普通网页同样提示避开已用题。提交题卡前再次核对，即使模型仍选了旧题，也反馈重复原因并让它在当前回合换题。重复不计入题面校验失败次数，不误触发「连续三次原文错误」终止。
5. **保留原题追问**：用户明确要求重看上一题、原题讲解或点名某一道题时，允许引用或恢复原题，不为了去重擅自换掉讲解对象；不增加永久禁止重看的规则。
6. **有界继续寻找**：先找同页/同份 PDF 的其他题，再调整关键词或换公开来源；保留已确认的读取时间、来源数、PDF 页数和运行步数预算。预算内只有旧题时明确说「本轮未找到可核对且未提供过的新题」，不把旧题包装成新题，也不承诺网上所有题都能读取。

## 接口与代码影响

| 位置 | 调用方及变更 |
| --- | --- |
| `services/web_question_history.py` | 通过已有会话归属读取当前教师/课程近期题卡，解析现有 JSON；计算题干/选项与原图比较信息，缓存到本轮上下文；不改变普通 `AgentStore.history()` 返回值 |
| `agent/tools/web_search.py`、`web_questions.py` | 搜索与原文读取返回必要的已用题提示，PDF 优先未用候选；`prepare_web_question` 提交前拒绝默认找新题场景中的重复题 |
| `agent/context.py`、共享工具及结束提示 | 两条运行路径共用工具实现与准确的重复耗尽提示；每轮独立锁保证 SDK 并发提交只发一张同题卡，不给其他用户加全局锁；运行层事件流程不变 |
| `skills/teacher_web_research.md` | 明确默认换新题、只重复原题的例外、预算耗尽说明，不通过提高随机性来碰运气 |
| 检查脚本与文档 | 新增连续找题、旧卡兼容、排版/题号差异、题意或图形变化、来源内多题、角色/课程隔离和显式重看测试 |

复用 `/api/v1/ai/chat`、`/api/v1/ai/chat/stream`，请求方不必新增参数；网页题与 PDF 题都走原有题卡工具。题卡仍记录在 `chat_messages.tool_log`。不加表、不加列、不做迁移，不改变 SSE 事件名称与字段。

## 用户可见变化

- 教师连续找同主题题时，优先得到内容不同的新题；同一份 PDF 可继续提供其他题，不整本排除。
- 已有历史题卡、图片缩放、双击预览及上下左右滚动保持可用；没有新题时给出准确反馈。
- 学生端、管理员端不新增联网或写入权限；三端窗口操作仍须用户点击确认。

## 失败与回退

历史中的坏 JSON 或旧卡缺少可选元数据时跳过无效项；核心归属查询失败时明确反馈，不能静默声称已完成去重。规范化仅用于比较，不修改原题显示、来源或原图。可关闭本轮去重接入，回退到现有选题流程，既有历史无需清理或迁移。

## 实施时验证出的读取改进

真实连续换题暴露了旧策略的两个瓶颈：第一份 PDF 一次用完 8 页预算，以及操作列表被当作习题页。现在首次读取一份 PDF 最多取 4 页，为其他来源留预算；可在本轮白名单来源 URL 后附 `#page=N` 再读 1 个未读文件页，并合并保留已读候选。同一来源不重复占不同来源数，重复页复用缓存，超出总页数或本轮预算明确拒绝；总限制仍为每轮 8 页、90 秒和既有来源上限。

页面排序优先真正的习题栏目、填空和问句，而非只看主题词出现次数。新题卡仍需通过原文与原图核对，不因去重降低完整性要求。题干比较保留数值、运算符和程序标识符，不把选项 `(1)`、`(2)` 当题号删除。
