## 二、核心规范：章节 + 知识点

**课程结构由 `graph_nodes` 一张表承载，靠 `graph_type` 区分两类节点。**

### 2.1 复合主键（重要）

`graph_nodes` 的主键是 **`(id, graph_type)` 复合键** —— 同一个 `id` 可以在不同类型下重复存在，因此**任何查询都必须同时带 `graph_type` 和 `course_id`**。

### 2.2 章节（`graph_type='chapter'`）

| 列 | 含义 | 实际值 |
|---|---|---|
| `id` | 章节 id | `CH01` … `CH09` |
| `name` | 章节名 | `第1章 绪论` … `第9章 排序` |
| `chapter` | 恒为空（章节节点不用此列） | `''` |

### 2.3 知识点（`graph_type='knowledge'`）

| 列 | 含义 | 实际值 |
|---|---|---|
| `id` | 知识点 id | `KP001` … `KP026` |
| `name` | 知识点名 | `数据结构概述`、`二叉树遍历` … |
| `chapter` | **所属章节名（字符串）** | `第6章 树和二叉树` |
| `difficulty` | 难度 1~5 | 现均为 2 |
| `is_key` | 是否重点 | 现均为 0 |
| `pos_x` / `pos_y` | 图谱编排坐标 | 已布点 |

### 2.4 章节 ↔ 知识点的关联方式

**关联键是「章节名字符串」**，不是 id，也没有外键：

```sql
-- 取某章的全部知识点
SELECT * FROM graph_nodes
WHERE graph_type = 'knowledge' AND course_id = ? AND chapter = '第6章 树和二叉树';
```

> ⚠️ 这是当前唯一可用的关联方式。实测 26 个知识点的 `chapter` 全部能对上 9 个章节节点的 `name`。
> 若将来要改成按 id 关联，需新增列并由教师端编辑入口同步维护。

### 2.6 关系边（`graph_links`）

| 列 | 含义 |
|---|---|
| `graph_type` | 与节点对应；当前只有 `knowledge` |
| `source` / `target` | 节点 id（KP id） |
| `relation` | `pre`（前置） / `advance`（后继） / `parallel`（并行） |

当前 11 条边，例：`KP003 --advance--> KP004`、`KP006 --parallel--> KP007`。

### 2.7 知识点详情（`kp_details`）

`kp_id` 为主键，冗余承载 `name` / `chapter` / `difficulty` / `pre_kp` / `post_kp` 等。
`graph_nodes` 是**结构权威**，`kp_details` 是**其扩展与统计位**。

> ⚠️ `kp_details.question_count`、`wrong_count`、`mastery_rate` 等统计字段**当前全为 0，不可信**，
> 需要统计时请实时聚合 `questions.answer_records`，不要读这些列。

## 三、内容表如何引用章节/知识点

| 表 | 章节字段 | 知识点字段 | 备注 |
|---|---|---|---|
| `questions` | `chapter_id` = `CH01..CH09`<br>`chapter` = 章名 | `kp_id` = 主 KP（单值）<br>`kp_ids` = JSON 数组（**当前全空**） | `kp_path` = `["章名","知识点名"]`，供展示 |
| `resources` | `chapter_id`、`chapter` | `kp_id` = 主 KP<br>`kp_ids` = JSON 数组（**65/65 都有值**） | 资源可挂多 KP |
| `learning_paths` | `chapter` | `kp_id` | 一人一行 · 26 行 |
| `answer_records` | —（经 `q_id` 关联） | `kp_id` | 答题记录 |
| `alerts` | —（经 `class_id`） | `kp_id` / `kp_name` | 预警 |

**查询范式（推荐写法）**：

```sql
-- 某课程的「章 → 知识点」树
SELECT c.id AS chapter_id, c.name AS chapter_name,
       k.id AS kp_id, k.name AS kp_name
FROM graph_nodes c
JOIN graph_nodes k
  ON k.graph_type = 'knowledge' AND k.chapter = c.name AND k.course_id = c.course_id
WHERE c.graph_type = 'chapter' AND c.course_id = :course_id
ORDER BY c.id, k.id;

-- 某知识点的题目
SELECT q_id, stem, difficulty, status FROM questions
WHERE course_id = :course_id AND kp_id = :kp_id AND status = 'published';

-- 某知识点的资源（多 KP 命中用 LIKE，注意 JSON 引号）
SELECT res_id, title, type FROM resources
WHERE course_id = :course_id AND kp_ids LIKE '%"' || :kp_id || '"%';
```

> `kp_ids` 是 JSON 文本。当前无 JSON1 扩展依赖，用 `LIKE '%"KP001"%'` 即可；若要精确匹配建议后续改用 `json_each`。

## 四、课程隔离要求（强制）

| 规则 | 说明 |
|---|---|
| 必带 `course_id` | 所有业务表查询必须显式过滤 `course_id`，**禁止**「不传就是全库」 |
| `course_id` 不给默认值 | 模型层历史默认值 `C2026DS001` 是孤儿课程，是串数据的根因。新列一律不给默认值 |
| 课程上下文来源 | 请求头 `X-Course-Id` → `dependencies.get_current_course_id()` → 查 `user_courses` 并做成员校验（非成员 403） |
| 会话/草稿 | `chat_sessions.course_id`、`st_question_drafts.course_id` 由写入方显式提供 |
| 无归属用户 | `user_courses` 无记录 → **400**，绝不回退到演示课 |

**已具备 `course_id` 的表**：`courses`(PK) · `user_courses` · `resources` · `questions` · `graph_nodes` · `graph_links` · `kp_details` · `learning_paths` · `answer_records` · `practice_sessions` · `chat_sessions` · `st_question_drafts` · `alerts` · `tags` · `reports`(经 class_id)

**经关联间接隔离**（不加列）：`chat_messages`（经 session）· `resource_progress`（经 resource）· `question_tags`（经 q_id）· `resource_tags`（经 res_id）

**个人/全局数据**（暂不隔离）：`users` · `classes` · `teacher_classes` · `teacher_class_data` · `messages` · `study_checkins` · `resource_study_log` · `intervention_templates` · `interventions`

## 五、用户与课程归属

```
users ──< user_courses >── courses
                role_in_course: teacher | student
```

- `users.user_id` 是业务主键（如 `Tbaiyin` / `Sstudent`），`username` 唯一索引用于登录。
- **"某课程有哪些人" 只查 `user_courses`**，不要用 `users.class_name`（老字段）。
- 教师建课时会写入 `courses` + `user_courses(role=teacher)`；学生凭 `courses.invite_code` 入课。

## 六、AI 层（agent_st 相关）

| 表 | 说明 |
|---|---|
| `chat_sessions` | 一次答疑会话。`session_id` PK（`CH`+hex）、`user_id`、**`course_id`**、`title`、`flow_id`、`rounds` |
| `chat_messages` | `session_id` + `role`(`me`/`ai`) + `content` + `citations`(JSON) + `tool_log`(JSON) + `draft_id` |
| `st_question_drafts` | 出题草稿。`draft_id` PK（`QD`+hex）、`user_id`、**`course_id`**、`batch_id`、`payload_json`、`status`(`draft`/`invalid`/`published`)、`errors_json` |

**隔离键**：会话与草稿都是 `user_id + course_id` 双维。前端历史会话列表按 **学生 id** 汇总（跨课程可见），出题草稿列表按 **course_id** 过滤。

## 七、题号（`q_id`）体系

| 前缀 | 来源 | 示例 |
|---|---|---|
