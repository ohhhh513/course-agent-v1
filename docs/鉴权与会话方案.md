# 鉴权与会话方案

> 适用对象：后端开发者（实现 `/auth/*` 接口）、前端维护者。
> 配套：`接口文档.md` §2 认证与公共、`后端对接指南.md`。

---

## 1. 总体流程（当前 http 模式）

```
浏览器                              前端                                 后端
  │                                    │                                    │
  │  访问 student.html / teacher.html   │                                    │
  │ ──────────────────────────────────▶ │  Auth.requireAuth(role)            │
  │                                    │  读取 localStorage.ca_session      │
  │                                    │  无会话 ──▶ 跳转 index.html        │
  │                                    │                                    │
  │  提交账号/密码 (index.html)         │  Auth.login → API.auth.login       │
  │ ──────────────────────────────────▶ │ ───── POST /auth/login ─────────▶ │
  │                                    │ ◀── { token(JWT), user } ──────── │
  │                                    │  写入 ca_session = { token, user }  │
  │ ◀──────── 跳转 student/teacher ──── │                                    │
  │                                    │                                    │
  │  后续请求自动带 Authorization 头     │  API.config.token = 'Bearer <JWT>' │
```

> 当前 `api.js` 固定 `mode='http'`，登录/找回密码等一律打真实后端（`backend/app/routers/auth.py`）。早期的前端 `mock` 账号表（`ca_accounts`）仅在 mock 模式启用，现已不再参与真实登录。

## 2. 会话存储（前端）

| Key | 内容 | 写入时机 |
| --- | --- | --- |
| `ca_session` | `{ token: 'Bearer xxx', user: { userId,name,role,... } }` | 登录成功 / 后端返回 user 时 |
| `ca_accounts` | 账号数组（**仅 mock 模式兜底**，当前未启用） | 早期原型种子；现以后端账号为准 |

> `ca_session` 仅用于前端快速读取当前用户（顶栏头像、路由守卫判断），**真实鉴权以 `Authorization` 头中的 JWT 为准**。JWT 由后端签发，`api.js` 在 `mode='http'` 时自动注入到每个请求头。

## 3. 接口契约（后端已实现）

### 3.1 登录 `POST /auth/login`
```jsonc
// request
{ "username": "student", "password": "123456", "role": "student" }
// response.data
{ "token": "<JWT>", "user": { /* 见 §5 User 实体 */ } }
```
- 校验账号 / 密码；失败返回 `code≠0` + 中文 `message`（`账号不存在` / `密码错误，请重试`）。
- 返回 `token`（JWT，含 userId / role 声明），前端存入 `API.config.token` 与会话。
- 学生登录会顺便记录当日学习打卡（`study_checkins`）。
- `role` 仅用于前端预选角色标签，后端以数据库中的真实角色为准。

### 3.2 获取当前用户 `GET /auth/profile`
```jsonc
// response.data → User（同登录返回的 user，教师额外带 classes）
```
- 身份由 `Authorization` 头解析，**无需**在 query 重复传 userId/role。

### 3.3 找回密码 `POST /auth/reset-password`
```jsonc
// request
{ "username": "student", "password": "newPass123" }
// response.data
{ "ok": true }
```
- **当前后端实现要求已登录**，且**只能重置当前登录账号**的密码（`req.username` 必须与 `current_user.username` 一致，否则 `403`）。
- 密码长度建议 ≥ 6；不足返回 `新密码至少 6 位`。
- ⚠️ **已知缺口**：公开页 `forgot.html` 的「免登录找回密码」流程尚未接入后端（后端要求先登录），正式环境需叠加验证码 / 安全问题等二次校验后再开放免登录找回。

### 3.4 退出 `POST /auth/logout`
- 后端原型仅返回成功；前端清除 `ca_session`、复位 `API.config.token`。

## 4. 路由守卫（前端 `auth.js`）

| 方法 | 行为 |
| --- | --- |
| `Auth.requireAuth(role?)` | 业务页加载时调用。**无会话 → 跳 `index.html`**；传入 `role` 且与会话角色不符 → 跳回自己端。返回 `false` 时调用方须 `return` 终止渲染 |
| `Auth.enter(role)` | 首页双角色卡点击：已登录且角色匹配 → 进对应端；否则 → 跳 `index.html?role=xxx`（登录页预选角色） |
| `Auth.logout()` | 清 `ca_session`，复位 token，跳 `index.html` |
| `Auth.applyUserBadge()` | 将当前用户注入顶栏（需页面提供 `#tbAvatar / #tbUserName / #tbUid`） |

业务页守卫示例（`student.html` / `teacher.html` 首行）：
```js
if (window.Auth && !Auth.requireAuth('student')) return;   // teacher 端传 'teacher'
```

## 5. User 实体（登录 / profile 返回）

由 `backend/app/utils.py` 的 `to_user_dict()` 组装，字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| userId | string | 用户唯一 ID（如 `S20260317` / `T100286`） |
| username | string | 登录用户名 |
| name | string | 姓名 |
| role | `'student' \| 'teacher'` | 角色，前端据此路由 |
| avatarChar | string | 头像首字（可选，前端兜底取 name 首字） |
| avatarColor | string | 头像底色（CSS 渐变，可选） |
| studentNo | string | 学号（student 用） |
| className | string | 班级（student 用；前端顶栏 `tbUid` 多取此字段） |
| title | string | 教师职称（teacher 用，如 `副教授`） |
| dept | string | 院系（teacher 用） |
| classes | array | 教师授课班级列表 `[{classId,name,studentCount}]`（仅 teacher） |

> 字段名务必与上方一致：前端 `Auth.applyUserBadge` 与守卫逻辑直接读取 `user.role / user.name / user.className / user.avatarChar` 等。多余字段可保留，缺失字段前端有兜底。

## 6. 角色模型

| 角色 | 入口页 | 视图数 | 核心能力 |
| --- | --- | --- | --- |
| `student` | `student.html` | 7 | 学习驾驶舱、三图谱导航、资源中心、AI 答疑、智能练习、我的学情、预警中心 |
| `teacher` | `teacher.html` | 7 | 教学驾驶舱、学情监测看板、归因分析、AI 出题、教学干预、学情报告、资源管理 |

角色在登录时由后端确定，会话中固化；守卫保证学生不能越权进入教师端，反之亦然。

## 7. 前端依赖的后端能力小结

1. 签发可解析 userId/role 的 JWT（`/auth/login`）。
2. 所有受保护接口校验 `Authorization` 头，失效返回 `401` + 统一信封。
3. 提供 `/auth/profile`（按 JWT 返回 User）。
4. `/auth/reset-password` 当前仅支持「已登录重置本人密码」，免登录找回属于待补缺口。
5. 错误统一通过信封 `code/message` 返回，文案用中文，便于前端直接 `Toast` 展示。
