# 前端架构与运行说明

> 适用对象：前端维护者与后端对接开发者。
> 配套文档：`接口文档.md`（API 契约）、`后端对接指南.md`（联调步骤）、`鉴权与会话方案.md`、`数据模型与Mock说明.md`、`页面与功能清单.md`。

---

## 1. 项目定位

「课程智能体系统」前端原型（v1.0），覆盖**学生端**与**教师端**两大角色，围绕「知识图谱 / 问题图谱 / 目标图谱」三大图谱驱动学情监测与精准教学。

- **纯静态原型**：原生 HTML + CSS + JavaScript，无框架、无打包构建步骤，浏览器直接打开即可运行。
- **ECharts** 经 `assets/js/vendor/echarts.min.js` 本地引入，离线可用。
- **数据直连后端**：所有取数统一经过 `API` 封装层；当前 `api.js` 的 `config.mode = 'http'`，直接请求真实后端的 `/api/v1`，页面零改动。

> **Mock 已下线**：早期的 `assets/js/mock/data.js` 与 `mode:'mock'` 已移除。前端现在只消费真实后端接口；若后端未启动，页面会直接报接口错误而非回退到假数据。

## 2. 技术栈

| 维度 | 选型 |
| --- | --- |
| 语言 | HTML5 / CSS3 / ES6+（原生，无 TypeScript） |
| 样式 | 原生 CSS，CSS 变量驱动主题；无预处理器、无 UI 框架 |
| 脚本 | 原生 JS（全局命名空间 + 模块化目录，非 ES Module） |
| 图表 | ECharts 5（`vendor/echarts.min.js`，本地托管） |
| 路由 | 自研 hash 路由（`Router`，`location.hash` 切换视图） |
| 存储 | `localStorage`（会话 `ca_session`、账号兜底 `ca_accounts`） |
| 运行 | 任意静态服务器（如 `python3 -m http.server`）或由后端挂载根路径 |

## 4. 脚本模块职责

| 模块 | 全局符号 | 职责 |
| --- | --- | --- |
| `common.js` | `U`、`icon`、`Theme`、`Toast`、`Modal`、`Router`、`initTopbar` | 基础设施：图标 SVG（`ICONS`）、DOM 工具 `U`、`countUp`/`ring`/`bar`、`Theme`、`Toast`/`Modal`、`Router`（hash 视图切换）、顶栏初始化 |
| `auth.js` | `Auth` | 账号表读写（兜底）、演示账号种子、登录、找回密码、登出、`requireAuth(role)` 路由守卫、`enter(role)` 入口跳转、`applyUserBadge()` 顶栏用户注入 |
| `api.js` | `API` | **统一取数入口**。按业务分模块：`auth` / `graph` / `student` / `ai` / `practice` / `teacher` / `analysis` / `question` / `intervention` / `report`。每个方法注释即接口契约 |
| `charts.js` | `Charts` | ECharts 实例工厂与常用图（折线、柱状、雷达、饼、热力、关系图、仪表盘），统一主题色 |
| `student/app.js` / `teacher/app.js` | — | 端内顶栏初始化、全局事件、班级选择（教师端）等 |
| `student/start.js` / `teacher/start.js` | — | 路由启动：注册所有视图并 `Router.init()` |
| `student/views/*.js` / `teacher/views/*.js` | — | 各自端内视图的 `mount/update` 渲染、事件绑定、调用 `API.*` 取数 |

> **全局加载顺序约定（重要）**：每个 HTML 按 `vendor/echarts → common → charts → api → auth → <role>/app → <role>/views/* → <role>/start` 顺序引入，保证全局符号就绪。新增脚本务必遵循此依赖链（以 `student.html` 为准）。

## 5. 与后端的连接机制

`assets/js/api.js` 顶部 `config` 控制数据来源（当前固定为 http）：

```js
const config = {
  mode: 'http',                 // 当前固定为 http，直连真实后端
  baseURL: '/api/v1',
  token: 'Bearer <JWT>',        // 登录后由后端返回并写入
  latency: [120, 380]           // 仅 mock 模式生效
};
```

- **mode='http'**：`request()` 使用 `fetch` 调用 `baseURL + path`，`GET` 参数拼 query，`POST/PUT/DELETE` 用 JSON body，并自动注入 `Authorization: <token>` 头；登录返回的 `token` 写入 `localStorage.ca_session`，后续请求自动带上。
- 响应统一读取 `data`；`res.code !== 0` 时抛异常，页面 `.catch()` 处理。
- 页面代码**只调用 `API.<module>.<method>(payload)`**，不直连任何数据源。后端只需实现 `接口文档.md` 中列出的接口，前端即可消费，**无需修改任何页面代码**。

## 6. 路由与多页面结构

本项目采用**多页面 + 单页视图**混合：

- **鉴权相关页**（独立 HTML）：`index.html`（登录）、`forgot.html`（找回密码）、`home.html`（产品介绍，可选）。
- **业务端页**（SPA 容器）：`student.html`、`teacher.html`。进入时由 `Auth.requireAuth(role)` 守卫，未登录自动跳 `index.html`。
- **端内视图**：通过 `Router`（hash 模式）在容器 `<section class="view" id="view-xxx">` 间切换，视图首次进入 `mount`、再次进入 `update`（避免重复渲染）。

## 7. 主题与设计变量

- 当前固定为亮色主题：`<html data-theme="light">`，`Theme` 模块仅提供 `set('light')`。
- 颜色、圆角、间距等通过 `base.css` 的 CSS 变量集中管理（`--brand-600`、`--surface-2`、`--r-md` 等）。业务样式均引用变量，禁止裸值。
- **图标**：`common.js` 内置 `ICONS`（Lucide 风格 stroke 图标），通过 `icon(name)` 渲染为内联 SVG；无显式尺寸的 SVG 由 `base.css` 兜底为 `1em`，避免被撑大。

## 8. 本地运行与预览

### 8.1 启动静态服务器

```bash
cd course-agent
python3 -m http.server 8080
```

## 9. 命名与编码约定

- **CSS 类**：`block`（如 `.auth-page`）、`block__elem`（BEM 风格）、修饰类 `block--mod`（如 `.btn--primary`）。
- **JS 全局**：仅 `U / icon / Theme / Toast / Modal / Router / Auth / API / Charts` 等有限的几个挂在 `window` 上；视图模块用对象字面量组织，避免污染。
- **接口字段**：小驼峰；时间统一 ISO 字符串；枚举值见各接口文档（`level`、`status`、`role` 等）。
- **错误提示**：业务异常通过响应信封 `message` 返回中文可读文案，前端直接展示。
