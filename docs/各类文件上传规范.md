# 各类文件上传规范

> 依据：当前工作区的前端页面、上传接口和文件解析代码。整理日期：2026-10-10。
>
> 本文中的“限制”指代码已有的校验；“建议”用于提高上传、解析和预览的成功率，不代表系统已经强制执行。不同入口支持的文件类型不能相互套用。

## 一、上传入口总览

| 上传入口 | 使用者 | 接受的扩展名 | 已实现的数量、大小限制 | 用途 |
| --- | --- | --- | --- | --- |
| 智能助手对话附件 | 学生、教师、管理员 | `.txt`、`.md`、`.csv`、`.json`、`.xlsx`、`.docx`、`.pdf`、`.jpg`、`.jpeg`、`.png`、`.gif`、`.webp` | 每次最多 5 个；每个不超过 10MB；本次图片合计不超过 32MB | 让助手参考文档或识别图片 |
| 课程资源：教材文献 | 教师端 | `.pdf`、`.doc`、`.docx`、`.txt` | 一次上传 1 个；代码未设置明确的单文件大小上限 | 发布教材、文献等学习资料 |
| 课程资源：课件 | 教师端 | `.pdf`、`.ppt`、`.pptx` | 一次上传 1 个；代码未设置明确的单文件大小上限 | 发布课件；PPT/PPTX 转成 PDF 预览 |
| 课程资源：教学视频 | 教师端 | `.mp4`、`.mov`、`.webm`、`.mkv` | 一次上传 1 个；代码未设置明确的单文件大小上限 | 发布视频资源 |
| 题库“导入题目” | 教师端 | `.txt`、`.md`、`.json`、`.csv`、`.xlsx`、`.docx`、`.pdf` | 每个文件不超过 10MB；每批 1～100 道题 | 解析、预览、确认后导入题库 |
| 账号管理“批量导入” | 管理员 | `.xlsx`、`.docx`、`.csv`、`.txt` | 每个文件不超过 10MB；每批最多 5000 条账号记录 | 批量创建学生或教师账号 |
| 管理员助手识别账号表 | 管理员 | 结构化账号表支持 `.xlsx`、`.docx`、`.csv`、`.txt` | 同对话附件限制；每个文件最多取前 200 条；一次账号导入动作最多 200 条 | 在对话中预览账号并审批导入 |
| 手动补充知识库接口 | 有相应课程权限的教师、管理员 | 实际解析支持 `.pdf`、`.pptx`、`.txt`、`.md` | 一次上传 1 个；代码未设置明确的单文件大小上限 | 添加供智能体检索的课程资料 |
| AI 智能出题“上传教材 / 课件 / 视频” | 教师端 | 页面提示 PDF、PPT、MP4 | **目前是模拟上传，无真实文件上传** | 当前不能用于保存或解析实际素材 |

大小说明：代码所称的 10MB、32MB 分别按 `10 × 1024 × 1024`、`32 × 1024 × 1024` 字节计算。课程资源和手动知识库入口没有明确的应用层大小上限，实际仍可能受服务器、代理、超时和磁盘空间限制。

权限说明：课程资源和题目接口的后端角色闸门允许教师、管理员，但还需通过当前课程的成员权限校验；现成上传页面主要位于教师端。学生不能通过这些接口发布课程资源或导入题库。

## 二、通用准备要求

1. **保留真实扩展名。** 将图片重命名为 PDF，或将 DOC 重命名为 DOCX，不会转换文件格式。
2. **优先使用 UTF-8 编码。** 题目导入的 TXT、MD、JSON、CSV，以及手动知识库的 TXT、MD，均应保存为 UTF-8；题目导入允许带 UTF-8 BOM。
3. **供 AI 分析的 PDF 尽量使用可选中、复制文字的版本。** 当前文档解析没有通用 OCR。扫描 PDF 可以用于资源展示，但不保证能提取文字、导入题目或加入知识库。
4. **建议上传无密码、未加密的文档。** 某些入口可能接受加密 PDF 的文件结构，但后续阅读和文字提取仍可能失败。
5. **建议文件名简短、含义明确。** 例如 `第3章_栈与队列.pdf`。不要求添加 DOC、PPT、Ch01 等固定前缀；章节优先在页面上选择。
6. **表格导入优先使用 XLSX。** 将用户名、学号等列设为文本，避免前导零丢失或被转成科学计数法；需要导入的数据放在当前活动工作表中。
7. **不要依赖 Excel 尚未计算的公式。** 解析器读取的是保存的单元格值或公式缓存结果，建议导入前将重要公式列转为值。

## 三、智能助手附件规范

### 3.1 上传方式与限制

学生、教师和管理员的智能助手共用附件组件，规则一致：

- 每次发送最多带 5 个附件，文档和图片合并计算个数。
- 每个附件不超过 10MB；同一轮全部图片合计不超过 32MB。
- 32MB 仅限制图片合计，不能理解为所有附件合计的统一上限。
- 必须同时填写问题文字，例如“请根据附件总结这一章的重点”；仅选择文件不能作为空问题发送。
- 发送前可移除附件；图片以缩略图展示，双击可放大。图片不单独显示文件名。

### 3.2 各种文件如何被读取

| 文件类型 | 当前读取方式 | 内容准备要求 |
| --- | --- | --- |
| TXT、MD | 读取文本 | 使用清晰标题、段落，推荐 UTF-8 |
| CSV、JSON | 当作文本提供给模型 | 可用于分析数据；上传 JSON 不会自动校验业务结构或导入数据 |
| XLSX | 读取所有工作表中的单元格值 | 第一行建议写列名；聊天读取所有工作表，与题库、账号导入不同 |
| DOCX | 提取段落和表格中的文字 | 内嵌图片不会随文字提取自动变成模型图片输入 |
| PDF | 提取页面文字 | 扫描件、图片型 PDF 可能因无可提取文字而被拒绝 |
| JPG、JPEG、PNG、GIF、WebP | 保留图片字节，作为图像输入传给模型 | 画面清晰、文字可读；扩展名必须与图片文件签名一致 |

聊天文档单文件提取文本上限约 60000 字符，本轮文档文本合计上限约 80000 字符。超出时可能截断；剩余额度耗尽后继续添加文档会被拒绝。大文档建议按章节拆分，并明确需要分析的范围。

聊天附件**不接受**旧版 DOC、XLS、PPT/PPTX、音频、视频，以及 BMP、SVG、HEIC 等图片格式。PPT 可先导出为 PDF，再作为聊天附件发送。

### 3.3 识图能力的条件

代码会将支持的图片格式作为模型图像输入，而不只是发送文件名。但识图是否成功，还取决于后端配置的模型和 API 是否支持图像输入。演示模式不具备真实图片识别能力。

图片上传校验目前使用文件签名识别格式，不能等同于完整图像解码、完整性审计或所有模型都支持动态 GIF。为便于分析，建议使用静态 JPG、PNG 或 WebP。

### 3.4 保存与再次编辑

- 原始图片和文档会保存到后端附件目录；刷新后可从原会话重新展示。
- 点击用户消息的重新编辑按钮，会恢复文字和对应附件，便于再次发送。
- 原文件名、附件标识、类型和大小保存在现有消息的附件元数据中；文件字节保存在磁盘上。
- 附件正文和图片主要用于上传当轮的模型输入。历史消息能展示附件，不代表之后每一轮都会自动重新读取其完整内容；需要重新分析时，建议通过重新编辑带回附件。
- 上传聊天附件不会自动将资料发布到课程资源，也不会自动加入长期知识库或正式题库。

## 四、教师课程资源上传规范

### 4.1 操作入口

- **课程资源管理 → 上传资源**：先选择资源类型，再选择文件；可填写标题、章节和知识点标签。
- **课程目录 → 上传资源**：同样选择资源类型；该页面要求选择所属章节后再上传。

选择的类别决定允许的扩展名。PDF 可以自行归入“教材文献”或“课件”，不由文件名自动决定。

### 4.2 类型、在线预览与知识库处理

| 自选资源类型 | 允许文件 | 当前在线阅读或播放 | 自动加入 AI 知识库 |
| --- | --- | --- | --- |
| 教材文献 | PDF | PDF 阅读窗口 | 后台提取文字后尝试入库 |
| 教材文献 | DOC、DOCX | 当前主要提供下载，不转换为在线 Word 阅读 | 当前不自动入库 |
| 教材文献 | TXT | 当前主要提供下载 | 后台尝试入库；推荐 UTF-8 |
| 课件 | PDF | PDF 阅读窗口 | 后台提取文字后尝试入库 |
| 课件 | PPT、PPTX | 后端转换成 PDF，再用 PDF 阅读窗口 | 使用转换后的 PDF 提取文字并尝试入库 |
| 教学视频 | MP4、MOV、WebM、MKV | 通过视频播放器；是否可播放取决于浏览器和编码 | 当前不自动转写、入库 |

PDF 阅读窗口的“全屏阅读”按钮位于标题栏右上角、关闭按钮旁，支持退出全屏；PPT 资源的“下载原文件”仍下载原始课件。

### 4.3 文件真实性校验

课程资源不是只检查扩展名，还会检查所选类别和文件内容：

| 文件 | 代码检查内容 |
| --- | --- |
| PDF | PDF 标记和可识别的 PDF 结构 |
| TXT | 可解码的文本、非空内容，排除部分二进制控制字符 |
| DOCX、PPTX | Office ZIP 包中的必要文件与主文档内容类型 |
| DOC、PPT | OLE 容器和 Word / PowerPoint 特征流；依赖 `olefile` |
| MP4、MOV | ISO 媒体容器结构 |
| WebM、MKV | EBML 容器及相应文档类型、分段结构 |

例如，选择“教学视频”后上传 PDF，或把 PPTX 改名为 DOCX，都会因类型不匹配被拒绝。应重新选择类别或上传正确文件。

这些检查验证文件格式和部分结构，**不保证所有内容完整、视频编码均能播放或文档文字均能提取**。视频建议采用浏览器普遍支持的 MP4，且使用兼容的音视频编码。

### 4.4 PPT/PPTX 转 PDF 的条件

- 当前代码已接入后端 LibreOffice 转换；仅后端电脑或服务器需要安装，学生和教师的浏览器设备不需要安装。
- 未安装转换器、转换失败或超时，本次 PPT/PPTX 上传会提示失败，不新增课程资源记录或发布源文件。
- 不依赖转换器的替代方式是自行导出 PDF，然后选择“课件”上传。
- 原 PPT/PPTX 与派生 PDF 一同保存。PDF 为静态内容，不保留动画、交互和音频；排版受服务器字体影响。
- 历史 PPT 不会自动批量补生成 PDF，需重新上传。

部署说明见 [课件在线预览部署.md](课件在线预览部署.md)。该文档也记录了当前真实转换和浏览器验收的范围。

### 4.5 上传成功与 AI 入库是两个结果

资源先保存，再通过后台任务提取文字、切片和建立检索数据。因此：

- 学生能打开 PDF，不代表该 PDF 已成功加入智能体知识库。
- 扫描 PDF 可能能阅读，但提取不到文字，导致知识库入库失败。
- TXT 上传校验可接受部分中文编码，但知识库文本解析使用 UTF-8；建议统一使用 UTF-8。
- Word 和视频目前可以作为资源保存，但没有自动知识库解析。

教师可关注上传后的知识库处理结果。处理失败时应检查文档是否有可提取文字、文本编码和模型向量服务配置。

## 五、教师题库文件导入规范

### 5.1 当前推荐流程

在教师端题库点击“导入题目”，选择文件或粘贴文字，完成解析预览，核对、修改并再次解析，确认无错误后导入。

该流程支持 TXT、MD、JSON、CSV、XLSX、DOCX、PDF；每个文件不超过 10MB，每批 1～100 道题。预览不创建题目，确认后题目以**待审核**状态保存，不直接发布。

粘贴文字或按普通文本解析的内容上限为 80000 字符。DOCX、PDF 先提取文字，提取阶段超过约 60000 字符会截断；长文档应分批导入，避免后面的题目遗漏。

### 5.2 题目内容要求

| 项目 | 规范 |
| --- | --- |
| 题型 | 当前导入预览仅支持单选、多选；JSON 用 `single`、`multi`，也接受“单选题”“多选题”等中文值 |
| 题干 | 必填，最多 20000 字符 |
| 选项 | 2～8 个；字母为 A～H，字母不得重复，选项文字不能为空 |
| 答案 | 必填，必须对应已有选项；单选仅一个字母，多选建议使用不重复的多个字母，例如 `AC` |
| 解析 | 可选，最多 20000 字符 |
| 难度 | 整数 1～5；未提供时默认 3 |
| 分值 | 整数 1～100；未提供时默认 5 |
| 章节、知识点 | 可在导入窗口统一选择；文件中若提供关联标识，必须属于当前课程 |
| 题图 | 当前预览不直接接收题图结构；含图片的题目需到题目编辑器核对保存 |

这里的多选类型是 `multi`，不要在导入 JSON 中写 `multiple`。判断题、简答题不能套用该预览入口的格式直接导入。

### 5.3 TXT、MD、DOCX、PDF 的建议排版

TXT、MD 使用 UTF-8。DOCX、PDF 必须能提取出以下文字结构，不能只放题目截图。

```text
1. 哪种数据结构遵循先进先出原则？
A. 栈
B. 队列
C. 树
D. 图
答案：B
解析：队列在队尾入队、队头出队，遵循先进先出原则。

2. 下列哪些属于线性数据结构？
A. 顺序表
B. 链表
C. 栈
D. 树
答案：ABC
解析：顺序表、链表和栈都属于线性数据结构。
```

题号、选项和“答案：”“解析：”建议各占一行。PDF 和 DOCX 只是先提取文字，不能保证任意复杂排版都能识别；建议先用少量题目预览验证。

### 5.4 CSV、XLSX 表格模板

第一行为表头，一行一道题。建议使用下列表头：

| 题干 | A | B | C | D | 答案 | 解析 | 题型 | 难度 | 分值 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 哪种数据结构遵循先进先出原则？ | 栈 | 队列 | 树 | 图 | B | 队列遵循先进先出原则。 | 单选题 | 2 | 5 |
| 下列哪些属于线性数据结构？ | 顺序表 | 链表 | 栈 | 树 | ABC | 前三项属于线性数据结构。 | 多选题 | 3 | 5 |

对应 CSV 示例：

```csv
题干,A,B,C,D,答案,解析,题型,难度,分值
哪种数据结构遵循先进先出原则？,栈,队列,树,图,B,队列遵循先进先出原则。,单选题,2,5
下列哪些属于线性数据结构？,顺序表,链表,栈,树,ABC,前三项属于线性数据结构。,多选题,3,5
```

表格注意事项：

- XLSX 只读取活动工作表；不要把待导入内容分散在多个工作表。
- CSV 使用 UTF-8，可带 BOM；题库 CSV 使用标准 CSV 解析，带英文逗号或换行的单元格应按 CSV 规则加双引号。
- 选项列表按需要设置 A～H 列，不要添加没有内容的多余选项列。
- 一批只放最多 100 道题；解析器不会无限遍历超大表格，超量文件应自行拆分。
- 中文表头支持“题干”或“题目”、“答案”、“解析”、“题型”、“难度”、“分值”。

### 5.5 JSON 模板

可使用题目数组，也可使用 `{ "questions": [...] }` 包装。以下示例不需要填写内部章节、知识点编号，可在页面选择归属：

```json
{
  "questions": [
    {
      "stem": "哪种数据结构遵循先进先出原则？",
      "type": "single",
      "options": [
        { "key": "A", "text": "栈" },
        { "key": "B", "text": "队列" },
        { "key": "C", "text": "树" },
        { "key": "D", "text": "图" }
      ],
      "answer": "B",
      "analysis": "队列遵循先进先出原则。",
      "difficulty": 2,
      "score": 5
    }
  ]
}
```

当前推荐导入窗口不直接接受 JPG、PNG 等图片。可先把图片发给具备识图能力的智能助手，整理成题干、选项、答案后，再进入导入预览核对；识别结果不能跳过人工核对直接作为正确答案。

## 六、管理员账号批量导入规范

### 6.1 页面与文件要求

入口为管理员端“账号管理 → 批量导入”。先选择导入学生或教师账号，再上传文件；推荐先下载该页面提供的 XLSX / DOCX 模板。

- 支持 XLSX、DOCX、CSV、TXT；每次 1 个文件，文件不超过 10MB。
- 每批最多 5000 条解析后的账号数据，已识别的表头不计入数据条数。
- 只能批量导入学生或教师账号，不能通过该入口导入管理员账号。
- 上传后先预览，核对有效、重复和错误行，再选择要导入的有效行并确认。

### 6.2 学生账号模板

| 用户名 | 姓名 | 密码 | 班级 | 学号 |
| --- | --- | --- | --- | --- |
| s_zhangsan | 张三 | 示例密码123 | 计算机2301班 | 20230101 |
| s_lisi | 李四 | 示例密码456 | 计算机2301班 | 20230102 |

### 6.3 教师账号模板

| 用户名 | 姓名 | 密码 | 部门 | 职称 |
| --- | --- | --- | --- | --- |
| t_wang | 王老师 | 示例密码123 | 计算机学院 | 讲师 |
| t_li | 李老师 | 示例密码456 | 计算机学院 | 副教授 |

上表密码仅用于说明格式，实际应自行设置。

### 6.4 字段与解析规则

- 用户名、姓名不能为空；实际采用的密码至少 6 个字符。班级、学号、部门、职称可按需要填写。
- 若页面填写了“统一初始密码”，它会**优先于文件中的密码**；未填写统一密码时使用每行的密码。
- 文件中重复的用户名、数据库中已存在的用户名会标记并跳过，不覆盖已有账号。
- 首行至少命中两个已支持表头时，按表头映射。建议直接使用上面的中文模板，避免依赖内部字段英文名；例如英文 `username` 当前不在表头别名中。
- 无可识别表头时，学生按“用户名、姓名、密码、班级、学号”顺序读取；教师按“用户名、姓名、密码、部门、职称”顺序读取。
- XLSX 只读取活动工作表，并跳过全空行。
- DOCX 优先读取表格；有表格数据时不会再将正文段落合并导入。建议整份名单放在一个表格，避免多个表格重复表头。

**账号 CSV / TXT 与题库 CSV 的解析不同：**账号文件按制表符、逗号、分号、竖线等直接切列，不支持完整 CSV 引号转义，并会丢弃空字段。因此账号字段中不要包含这些分隔符，也不要用连续逗号表示空列。需要留空或包含复杂文字时，使用 XLSX 或 DOCX 表格。

账号 CSV 示例：

```csv
用户名,姓名,密码,班级,学号
s_zhangsan,张三,示例密码123,计算机2301班,20230101
s_lisi,李四,示例密码456,计算机2301班,20230102
```

### 6.5 通过管理员智能助手导入账号

管理员可在智能助手上传 XLSX、DOCX、CSV、TXT 账号表，并明确说明“请导入这些学生账号”或“请导入这些教师账号”。

- 仍遵守每次最多 5 个附件、每个不超过 10MB 的聊天限制。
- 结构化账号识别每个文件最多取前 200 条记录，单次导入动作最多 200 个账号。建议一次准备不超过 200 条，更多数据使用账号管理批量导入页面。
- 表中应提供至少 6 位的密码；该结构化附件流程没有批量导入页面的统一密码输入框。
- 系统会根据“班级 / 学号”或“部门 / 职称”等表头推断角色；没有线索时默认学生，必须核对预览中的角色。
- 上传文件不等于已创建账号，需要核对预览并确认执行审批动作。
- PDF、JSON 和图片可作为普通聊天附件，但不属于该账号表结构化解析器直接支持的格式。

## 七、知识库补充资料规范

这是教师、管理员使用的维护接口，不是普通聊天附件入口，也不会自动创建课程资源卡片。

接口：`POST /api/v1/agent/ingest/file`，使用 `multipart/form-data`。

| 项目 | 规范 |
| --- | --- |
| 文件 | 一次 1 个；实际可解析 PDF、PPTX、TXT、MD |
| PDF | 应有可提取文字；扫描件不提供通用 OCR |
| PPTX | 提取幻灯片文字，不识别其中的图片内容 |
| TXT、MD | UTF-8 编码 |
| 章节 | 可选，必须属于当前课程 |
| 知识点 | 可选；多个标识使用英文逗号分隔，必须属于当前课程 |
| 大小 | 当前接口没有明确的应用层字节上限 |

特殊情况：入口扩展名列表包含 `.ppt`，但实际解析器会拒绝旧版二进制 PPT，并要求另存为 PPTX 或 PDF。该手动接口没有接入教师课程资源上传的 PPT 转 PDF 流程，因此建议直接使用 PPTX 或 PDF。

同一课程再次上传同名文件，会使用相同的磁盘位置和知识库来源标识；按替换同名补充资料处理。想保留两份资料时应使用不同文件名。

该接口先保存文件再解析，因此解析失败时文件可能已经落盘，不能将其错误处理与课程资源上传混为一谈。

## 八、历史接口与演示入口说明

### 8.1 历史题目文件直导接口

代码仍保留 `POST /api/v1/question/import/file`。它与当前“解析预览 → 确认导入”流程不同，会在解析后直接写入待审核题目，当前导入窗口主要使用新预览接口。

历史接口存在 DOCX、DOC、PDF、TXT 和部分图片分支，但不能据此扩展当前页面的支持范围：

- DOC 分支使用 DOCX 解析库，不能保证解析真正的旧版 `.doc`。
- 图片分支依赖 Pillow、pytesseract、Tesseract 程序以及中英文识别数据；缺少任一条件可能失败。
- PDF 分支依赖 pdfplumber，解析方式与当前预览流程不同。
- 该接口没有采用新预览入口的统一 10MB、100 题校验，旧文本解析也更受排版限制。

日常导入应使用当前题库“导入题目”窗口，避免绕过预览核对。

### 8.2 AI 智能出题的素材上传区

当前“上传教材 / 课件 / 视频”弹窗提供的是“选择文件（演示）”“模拟上传”。后端 `/api/v1/question/materials` 接收素材名称等 JSON 信息并返回占位任务，不接收实际文件内容，也不保存真实素材。

需要真实保存教材、课件或视频时，应使用教师课程资源上传入口；不能把模拟上传显示的进度作为实际解析成功的依据。

## 九、文件保存位置与设备迁移

以下路径均相对于项目根目录；聊天和知识库目录可通过 `AGENT_DATA_DIR` 配置改变。

| 文件来源 | 默认保存位置 | 说明 |
| --- | --- | --- |
| 智能助手图片、文档 | `backend/app/data/st/uploads/chat_attachments/{标识前2位}/{标识剩余部分}` | 使用随机标识，不保留原扩展名；原名称、类型等存于消息元数据，看到无扩展名文件属于正常现象 |
| 课程资源原件 | `resources/{课程ID}/{资源ID}/{文件名}` | 每个资源独立目录，不在 `backend/app/data` 内 |
| PPT 派生 PDF | `resources/{课程ID}/{资源ID}/{原文件名}.preview.pdf` | 与课件原件一同保留 |
| 资源封面 | `resources/covers/{资源ID}.jpg` | 系统自动生成 |
| 手动知识库资料 | `backend/app/data/st/uploads/{课程ID}/{文件名}` | 同课程同名文件使用同一路径 |
| 题目导入原文件 | 当前预览流程不长期保留原文件 | 保存的是确认导入后的题目；原文件请自行留存 |
| 账号批量导入原文件 | 页面导入流程不长期保留原文件 | 保存的是创建后的账号；若经聊天上传，则另按聊天附件规则保存 |

默认聊天上传目录与 `resources/` 内容均被 Git 忽略，推送代码到 GitHub 不会自动带上这些文件。

迁移到另一台设备时：

- **聊天附件**：需要一起复制主数据库 `backend/app/data/course_agent.db` 和实际附件目录，保留相对路径。
- **课程资源**：还需要复制项目根目录的 `resources/`；仅复制 `backend/app/data/` 不会带上教材、课件和视频原件。
- **知识库**：需要保留实际配置的知识库数据文件及上传目录，默认位于 `backend/app/data/st/`。
- 若修改过存储路径配置，应按实际路径迁移；还要保证新后端能够读到文件、前端资源请求指向新后端。

## 十、常见失败及处理

| 现象 | 优先检查 | 处理方式 |
| --- | --- | --- |
| 文件选择框看不到文件 | 当前入口支持的扩展名 | 选择正确入口，或使用软件另存为支持格式 |
| 提示资源类型不匹配 | 所选“教材文献 / 课件 / 教学视频”和真实文件格式 | 重新选择类型或上传正确文件，不要只改扩展名 |
| 提示附件过大或过多 | 10MB、5 个、图片合计 32MB | 压缩、拆分或分次发送 |
| PDF 可以打开，助手却读不到文字 | 是否为扫描件或图片型 PDF | 先做 OCR 转为文本 PDF，或将相关页面作为图片发送给支持识图的模型 |
| PPT 上传提示无法转换 | 后端转换器、超时、文件损坏或加密 | 处理后端转换环境，或自行导出 PDF 上传 |
| 视频上传成功但无法播放 | 浏览器支持的容器和音视频编码 | 转为兼容编码的 MP4 后重新上传 |
| 表格只导入一个工作表 | 数据是否在活动工作表 | 将待导入内容放到活动工作表；聊天普通附件则会读取所有表 |
| 账号字段错位 | CSV 空字段、字段中的分隔符、表头 | 使用官方中文表头，优先改为 XLSX |
| 题目答案或选项报错 | 选项是否为空、字母是否重复、答案是否对应 | 在预览中修正后重新解析 |
| 图片刷新后不显示 | 数据库引用、附件目录、后端文件访问 | 一起迁移数据库和附件文件，保留路径 |
| 课程资源请求返回 404 | `resources/` 内是否存在 URL 对应文件 | 补齐原资源文件；只有数据库记录不能恢复原件 |
