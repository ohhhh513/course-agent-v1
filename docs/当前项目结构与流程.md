# 当前项目结构与流程

> 适用：从 Git 拉取本仓库后请务必第一时间查看

---

## 1. 与 v1.0 及「演示版」的关键差异

| 主题 | v1.0 / 早期演示版 | **当前版本** |
| --- | --- | --- |
| 课程资源 | **`resources/`** 放入预先搜好一批视频、PPT、教材 | **`resources/` 不再存放课程内容**；而是按课程隔离，保存由教师上传或 利用测试工具`dev_tools` 批量上传（**详见6.1到6.4，一定要查看，不然全手动上传很累的**） |
| 师生账号 | 登录页演示号 `student` / `teacher`（123456） | **无演示师生**；仅内置管理员 **`admin` / `admin`**，由管理员开通账号 |
| 业务数据 | 启动时 `run_seed` / `bootstrap` 灌演示课与图谱 | **默认不灌演示数据**；库表建好后全部走真实 API/界面产生 |
| 学情与统计 | 部分接口曾依赖写死班级/假数据 | **已改为按当前课程（`X-Course-Id`）查库计算** |
| 启动入口 | 空库自动 seed 一套演示课 | 空库：建表 + 创建 admin；业务靠建课/导入 |

若启动日志仍出现大量 `[bootstrap] 图谱已扩展`、`[seed] …`，说明跑的是**旧 main** 或误开了 `DEMO_SEED=1`（见下）。

## 3. 标准启动流程（新目录）

### 3.1 环境

配置：`copy backend\app\.env.example backend\app\.env`  
- 主要是`LLM_API_KEY` / `EMBEDDING_API_KEY`（但当前由于数据库调整，这两个功能应该是有bug的）

### 3.2 启动

```bat
:: 项目根
start.bat
:: 或
cd backend && python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

预期启动日志要点：

```text
[startup] 数据库表已就绪（空库可直接使用）
[admin] 已创建管理员账号 admin/admin   （或「管理员已存在」）
[startup] 演示数据已关闭。请用 admin/admin 登录后创建教师与课程…
```

打开：<http://127.0.0.1:8000>

### 3.3 账号与课程（业务数据入口）

1. 登录页 → **管理员** → `admin` / `admin` → `admin.html`  
2. **新建教师 / 学生** 账号  
3. 教师登录 → 顶栏 **+ 新建课程** → 建章 / KP → **课程目录与资源** 上传文件、编知识图谱、导入/出题  
4. 顶栏 **「邀请码」** 可随时查看当前课邀请码  
5. 学生登录 → **加入课程** → 输入邀请码  

**不再提供** `student` / `teacher` 演示号；不再自动出现默认演示课 `C2026DS001` 的业务数据（除非你手动 `DEMO_SEED=1`）。

### 3.4 演示模式（可选，本地）

仅本地需要旧演示库时：

```bat
set DEMO_SEED=1
start.bat
```

会执行旧 `run_seed` / `bootstrap`。**团队协作与验收请保持默认关闭。**

## 4. 课程资源：`resources/` 的定位

| 点 | 说明 |
| --- | --- |
| 磁盘布局 | `resources/{courseId}/{resId}/{文件名}`，封面在 `resources/covers/` |
| 与 v1.0 区别 | **不再**内置 `data-structures-1-9` 那套「搜好就分发」的目录 |
| 如何进入系统 | ① 教师端上传 ② `dev_tools/init_course.py` 按配置批量传 |
| Git | 仅 `resources/.gitkeep`；**媒体一律不进仓库** |
| 同事拉取后 | 各自准备文件，或共用网盘后改本地路径再上传 |

访问 URL 与磁盘一一对应：`/resources/{courseId}/{resId}/文件名`。

## 5. 业务数据从哪来（真实库）

- 表结构：`backend/app/models/`  
- 启动只 `init_db()` 建表  
- 课程、章、KP、资源、题目、学习路径、练习记录等 **全部由 API/界面写入**  
- 列表与看板按 **`X-Course-Id`** 过滤当前课；无课时接口返回「尚未创建或加入课程」，**不回退**演示课号  

排查「是否有数据」：登录对应师生 → 教师顶栏选中课程 → 看目录/题库/驾驶舱是否为空（空课为 0 是预期，不是 bug）。

## 6. `dev_tools/`：开发批量上传（不进业务启动）

### 6.1 定位

| 项 | 说明 |
| --- | --- |
| 目的 | 省去在界面上点几十次上传/建 KP，**批量**建一门课的目录、传资源、导题 |
| 与系统关系 | **独立**；**不会**被 `main.py` / `uvicorn` 自动执行 |
| 运行方式 | **先启动后端**，再对 `http://127.0.0.1:8000` 发 **HTTP API** |
| 适用 | 本地联调、演示验收、初始化测试课 |

`dev_tools` **不是**线上数据通道，也不是启动依赖；同事可以完全不用它，改用手动建课上传。

### 6.2 目录内文件

| 文件 | 作用 |
| --- | --- |
| `README.md` | 简要说明 |
| `init_course.py` | 建课 + 章/KP + 上传资源（+ 可选题库） |
| `import_questions.py` | 仅导入题库到已有课 |
| `convert_after_class.py` | 将旧 `after_class.json` 转成导入契约（目录下已经有转换好的`questions_after_class_import.json`） |
| `course_structure_ds.json` | 数据结构课的章/KP/资源清单 |
| `questions_after_class_import.json` | 转换后的题库 |
| `sample_config.json` | 最小配置样例（忽略，没用） |

### 6.3 修改上传目标（教师 / 课程 / 文件来源）

打开配置 JSON（如 `course_structure_ds.json` 或你自己复制的 `my_course.json`）：

**教师**

```json
"teacher": {
  "username": "dev_teacher",
  "password": "123456"
}
```

改为你自己本地登录管理员账号创建好的的教师账号；密码为该教师登录密码。

**课程**

```json
"course": {
  "name": "数据结构与算法",
  "term": "2026 秋",
  "useCourseId": null
}
```

- `useCourseId: null` → 调 `POST /teacher/courses` **新建课**  
- `"useCourseId": "CXXXXXXXX"` → 使用已有课（**该教师必须已加入**）；会跳过建课  

**章节与知识点**

```json
"chapters": [
  { "name": "第1章 绪论", "kps": ["数据结构概述", "算法与算法评价"] }
]
```

`name` / `kps` 为中文名字符串；导入题库时靠名称匹配成课内 `kp_id`，**先建 KP 再导题**。

**被上传文件的来源**

```json
"resources": [
  {
    "file": "D:/本机路径/到/PPT_Ch01_绪论.pptx",
    "chapter": "第1章 绪论",
    "kps": ["数据结构概述"],
    "title": "第1章 绪论（课件）"
  }
]
```

| 字段 | 含义 |
| --- | --- |
| `file` | **本机绝对路径或相对项目根的路径**；脚本只读该文件再 multipart 上传 |
| `chapter` | 必须与 `chapters[].name` **完全一致** |
| `kps` | 该资源挂到的 KP 名列表（可多选；教材可挂本章全部 KP） |
| `title` | 界面显示名 |

**路径注意：** 示例 JSON 里若写的是别人机器上的 `D:/all_contest/...`，**你本机必须改成自己的文件位置**，否则会报「资源文件不存在」。

**题库（可选）**

```json
"questionsFile": "dev_tools/questions_after_class_import.json"
```

或仅导题：

```bat
python dev_tools\import_questions.py --course <课号> --dry-run
python dev_tools\import_questions.py --course <课号>
```

### 6.4 推荐执行顺序

```bat
:: 1. 后端已启动

:: 2. 若尚未有教师：管理员界面先建号

:: 3. 只建目录（不传文件）
python dev_tools\init_course.py --config dev_tools\your_config.json --skip-uploads

:: 4. 完整初始化（建课+章KP+传资源；配置里写好 file 路径）
python dev_tools\init_course.py --config dev_tools\your_config.json

:: 5. 已有课只导题
python dev_tools\import_questions.py --course <courseId>
```

成功输出含 **`courseId`、`inviteCode`**；把邀请码给学生即可。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 登录无 student/teacher | 用 `admin/admin` → 新建账号 |
| 启动像旧版（bootstrap 扩 9 章） | 确认分支/提交；勿设 `DEMO_SEED=1`；确认 `backend/app/main.py` 为新版 |
| 课程目录「未加入课程」 | 先建课或选课；顶栏课程下拉应有课 |
| 上传脚本找不到文件 | 改配置里 `file` 为本机真实路径 |
| 拉取后仍有 `*.bak`、`111.txt` | 多半是主分支历史或本地残留；用 `.gitignore` 挡住新提交；历史文件需维护者 `git rm` 后提交 |
| AI 不生成 | 检查 `.env` 是否配置 LLM；无 Key 为演示模式属预期 |
| 重启后登录失效 | `.env` 中固定 `JWT_SECRET` |

---

## 8. 一句话总结

**代码 + 文档进 Git；媒体进 `resources/`（手传）；账号进管理员界面；业务数据进数据库与 API；`dev_tools` 只帮你省批量点选时间，不参与系统启动，改配置里的教师、课号、`file` 路径即可对接你的本机素材。**
