# 课程智能体系统 · 接口文档（API v1）

> 适用范围：学生端与教师端前端（`course-agent/`）。
> 前端 `assets/js/api.js` 已固定 `config.mode='http'`，页面只通过 `API.*` 取数并**直连真实后端** `/api/v1`。（早期 `mock` 模式与 `assets/js/mock/data.js` 已下线。）
> **实时权威文档**：<http://127.0.0.1:8000/docs>（FastAPI Swagger 自动生成，永远与代码同步）。本文档提供契约说明与**实现状态标注**。

**状态标注说明**（本次新增，对应 `项目真实交互梳理.md`）：

| 标记 | 含义 |
| --- | --- |
| ✅ | 真实实现（真实读写数据库 / 真实算法 / 真实 LLM 调用） |
| ⚠️ | 真实实现，但当前受空数据影响输出为空或 0 |
| 🚧 | 占位 / 空壳（返回值硬编码或不落库） |

## 1. 约定

### 1.1 基础信息

| 项 | 值 |
| --- | --- |
| Base URL | `/api/v1` |
| 字符集 | UTF-8，`Content-Type: application/json`（文件上传用 `multipart/form-data`） |
| 鉴权 | `Authorization: Bearer <JWT>`，由 `POST /auth/login` 返回 |
| 请求约定 | `GET` 参数拼 query；`POST/PUT/DELETE` 用 JSON body |

### 1.2 统一响应信封

所有接口返回如下结构，前端统一读取 `data`：

```json
{ "code": 0, "message": "success", "data": { }, "traceId": "svc-xxxx" }
```

- `code === 0` 成功；`code !== 0` 为业务失败，前端展示 `message`（中文）。
- 全局异常处理器在 `main.py` 兜底：**HTTP 仍返回 200**，信封 `code=500`。
- ⚠️ 受保护接口 token 缺失/失效时返回 **HTTP 401**（`{"detail": "未登录或 token 缺失"}`），不走信封。

### 1.3 错误文案（前端据此提示）

| 场景 | message |
| --- | --- |
| 登录账号不存在 | `账号不存在` |
| 密码错误 | `密码错误，请重试` |
| 新密码过短（<6） | `新密码至少 6 位` |
| 其他异常 | 返回可读中文 `message`，前端 `Toast` 直接展示 |

### 1.4 列表分页

列表类接口统一返回 `{ total, list: [...] }`，支持 `page`（从 1 起）/ `size`。

> **特例**：`GET /teacher/classes` 返回**裸数组** `[{classId,name}]`（非 `{list}`），前端已兼容。**新增接口请勿混用两种形态。**

### 1.5 身份来源

身份（userId / role）由后端从 JWT 解析，**不要**依赖前端在 query/body 重复传 userId。

```jsonc

{ "ok": true }
```

```jsonc
// GET /graph response.data → Graph
{ "graphType": "knowledge",
  "categories": [ { "name": "已掌握", "color": "#22c55e" },
                  { "name": "学习中", "color": "#6366f1" },
                  { "name": "待加强", "color": "#f59e0b" },
                  { "name": "未开始", "color": "#64748b" },
                  { "name": "薄弱预警", "color": "#ef4444" } ],
  "nodes": [ { "id":"KP01", "name": "数据结构概述", "category":1, "mastery":13.3,
               "difficulty":2, "isKey":false, "hours":0, "x":25.6, "y":1.25 } ],
  "links": [ { "source":"KP001", "target":"KP002", "relation":"pre" } ] }
```
> - `mastery` 由 `answer_records` + `resource_progress` **实时计算**（非种子静态值）。
> - `nodes[].category`（知识图谱）是按学生真实学习状态计算出的**状态下标**（0 已掌握 / 1 学习中 /
>   2 待加强 / 3 未开始 / 4 薄弱预警），前端据此给节点上色；阈值见
>   `数据模型与字段说明.md` §2.3。未登录时统一按 3（未开始）返回。
> - `x` / `y` 为教师在「图谱编辑」里布点的坐标（为空则前端退回力导向布局）。

**推荐学习路径（`GET /graph/path`）**
```jsonc
// response.data
[ { "step":1, "kpId":"KP001", "name":"数据结构概述", "chapter":"第1章 绪论",
    "status":"doing", "hours":1, "mastery":13.3, "resCount":3, "progress":13.3,
    "quizMastery":0, "quizAnswered":false, "locked":false, "lockReason":"" } ]
```
> - `resCount` **以 `resources` 表为准实时统计**（主 `kp_id` + `kp_ids` 多标签都计入，
>   同一资源对同一知识点只算一次），不再直接读 `learning_paths.res_count` 这个派生缓存
>   （只在教师端上传/删除资源时同步，学生端会长期停在旧值 0）。返回前会把该生
>   过期的 `res_count` 一并回写，保证缓存与实物一致。
> - 前端「推荐学习路径」的章节行资源数按**去重后的资源条数**统计（同一资源挂多个知识点只算一次），
>   因此章节合计可能小于各知识点之和。

**资源学习进度写入（`POST /student/resources/{resId}/progress`）**
```jsonc
// request.body
{ "progress": 0-100,          // 完成百分比（服务端与旧值取 max，不回退）
  "position": 12,             // 视频=秒；文档/PPT=页码
  "watchedDelta": 3 }         // 可选：本次上报周期内「真正播放」的秒数，仅视频使用
```
> - `watchedDelta` 由前端按播放时间轴累加（暂停/缓冲/拖动都不计），服务端只把它累计进
>   `resource_study_log.watch_seconds`（当日观看时长 → 驾驶舱「今日累计学习」）。
>   缺省时退回「`position` 增量」，并做单次 ≤300 秒的上限保护，避免拖动进度条虚增学习时长。
> - 视频弹窗播放前会等到「整段缓冲完成 / `canplaythrough`」再播放与记录，
>   加载期间不写任何进度；记录点（`position`）即下次进入时的续播位置，已完成视频从头重播。
> - 静态资源目录 `/resources/**` 由后端按 HTTP **Range** 提供（`Accept-Ranges`/`206`/`416`），
>   否则浏览器把视频当不可定位流，无法跳转续播、每次都要从 0 字节重下。
> - ⚠️ `resource_progress` **没有 (user_id, res_id) 唯一约束**，历史并发上报会留下重复行
>   （同一资源两行，一行 0% 一行真实进度）。因此：
>   读一律走 `services/resource_progress.py::progress_map()`（同资源只取 `progress/position` 最优的一行），
>   写走 `consolidate()`（把重复行合并成一行并保留最大值）。前端 `save()` 也做串行上报（同一时刻只发一个请求）。
>   要彻底根治需要给该表加唯一约束 —— **属于表结构变更，需先确认**。


**驾驶舱结构**
```jsonc
// response.data
{ "overview": { "courseProgress", "currentNode": {...}, "streakDays",
                "todayStudyMinutes", "todayStudySeconds", "todayPracticeSeconds", "todayResourceSeconds",
                "status" },
  "coreMetrics": { "completionRate", "masteryRate", "goalAchieveRate", "updatedAt" },
  "todos": [ ... ], "weakPoints": [ ... ], "suggestedQuestions": [ ... ], "recentActivities": [ ... ] }
```

> - `todayStudySeconds` = 当天练习用时（`practice_sessions.duration_seconds`，进行中的会话按已答题用时合计）
>   + 当天视频观看秒数（`resource_study_log.watch_seconds`），按**本地日历日（东八区）**统计；
>   驾驶舱徽标「今日累计学习时长」即取该字段，并由 `/student/study-duration` 每 30 秒轻量刷新。
> - `todos[].target` 为前端已注册视图名：`resource`（继续学习，带 `kpName` 定位知识点）/
>   `practice`（继续挑战，带 `sessionId`） / `graph` / `alerts`。
> - `recentActivities` 由 `practice_sessions`（练习）与 `resource_progress`
>   （视频/课件/文献学习，`type: "resource"`）合并按时间倒序，各取最新若干条。

### 10.2 智能出题 `/question/gen`

```
meta(batchId,count) → tool_start / tool_end → draft(每题落库即推) → done(batchId,draftIds,demo,count)
```
> - 写入 `answer_records` 时 **`course_id` 取自练习会话**（`session.course_id`，回退题目/请求头）。
>   模型里 `course_id` 的列默认值是早期演示课 `C2026DS001`，真实库没有这门课，
>   **任何依赖默认值的写入都会外键失败**（历史上这里就因此 500，表现为前端"提交了没反应"）。
> - `kpPath` 长度不固定（2~3 级），前端按实际层级渲染。

**错题本（`GET /practice/wrong-book`）**
```jsonc
// response.data
{ "total": 12, "totalWrong": 12,
  "list": [ { "qId", "stem", "myAnswer", "answer", "wrongCount",
              "kpId": "KP013", "kpName": "树与二叉树",      // 知识点名（图谱名，不是裸 ID）
              "chapter": "第6章 树和二叉树", "difficulty", "lastTime", "mastered" } ],
  // 按「章节 → 知识点」归纳：章按「第N章」升序，知识点按错题数倒序
  "groups": [ { "chapter": "第6章 树和二叉树", "total": 1, "kpCount": 1,
                "kps": [ { "kpId": "KP013", "name": "树与二叉树", "count": 1 } ] } ] }
```
> - `mastered`：`false` 待攻克 / `true` 已掌握 / `all|缺省` 全部；`kpId`、`chapter` 只过滤 `list`。
> - **`groups` 反映当前分类**（待攻克/已掌握/全部），不受 `kpId`/`chapter` 影响 ——
>   这样选中某个知识点时，章节导航不会跳变，可以继续切换。前端据此做归纳面板的筛选。
> - 错题状态以**该题最近一次作答所在记录**的 `mastered` 为准（同一道题多次答错只算一条）。

## 10. SSE 流式事件协议

### 10.1 智能答疑 `/ai/chat/stream`

```
meta(sessionId,messageId) → tool_start / tool_end → think(模型推理) → content(逐 token) → citations → done(outOfScope)
```

| event | data |
| --- | --- |
| `meta` | `{ sessionId, messageId }` |
| `tool_start` / `tool_end` | `{ name, ... }` |
| `think` | `{ delta }`（deepseek `reasoning_content`，供思考面板） |
| `content` | `{ delta }`（逐 token） |
| `citations` | `{ items: [ {source,locator,quote,kp} ] }` |
| `done` | `{ outOfScope, demo }` |
| `error` | `{ message }` |

### 10.2 智能出题 `/question/gen`

```
meta(batchId,count) → tool_start / tool_end → draft(每题落库即推) → done(batchId,draftIds,demo,count)
```

| event | data |
| --- | --- |
| `meta` | `{ batchId, count }` |
| `draft` | `{ draft_id, status, errors, payload }` |
| `log` | 过程事件（原 `text` 类型） |
| `done` | `{ batchId, draftIds, demo, count }` |
| `error` | `{ message }` |

> `demo: true` 表示当前未配置 `LLM_API_KEY`，处于演示模式（出题会复制同章原题骨架）。
