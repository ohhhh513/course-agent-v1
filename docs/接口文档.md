# 课程智能体系统 · 接口文档（API v1）

> 适用范围：学生端与教师端前端（`course-agent/`）。
> 前端 `assets/js/api.js` 已固定 `config.mode='http'`，页面只通过 `API.*` 取数并**直连真实后端** `/api/v1`。（早期 `mock` 模式与 `assets/js/mock/data.js` 已下线。）
> **实时权威文档**：<http://127.0.0.1:8000/docs>（FastAPI Swagger 自动生成，永远与代码同步）。本文档提供契约说明与**实现状态标注**。

**状态标注说明**（本次新增，对应 `项目真实交互梳理.md`）：

| 标记 | 含义 |
| --- | --- |
| ✅ | 真实实现（真实读写数据库 / 真实算法 / 真实 LLM 调用） |
| ⚠️ | 真实实现，但当前受空数据影响输出为空或 0 |
| 🚧 | 占位 / 空壳（返回值硬编码或不落库） |

## 1. 约定

### 1.1 基础信息

| 项 | 值 |
| --- | --- |
| Base URL | `/api/v1` |
| 字符集 | UTF-8，`Content-Type: application/json`（文件上传用 `multipart/form-data`） |
| 鉴权 | `Authorization: Bearer <JWT>`，由 `POST /auth/login` 返回 |
| 请求约定 | `GET` 参数拼 query；`POST/PUT/DELETE` 用 JSON body |

### 1.2 统一响应信封

所有接口返回如下结构，前端统一读取 `data`：

```json
{ "code": 0, "message": "success", "data": { }, "traceId": "svc-xxxx" }
```

- `code === 0` 成功；`code !== 0` 为业务失败，前端展示 `message`（中文）。
- 全局异常处理器在 `main.py` 兜底：**HTTP 仍返回 200**，信封 `code=500`。
- ⚠️ 受保护接口 token 缺失/失效时返回 **HTTP 401**（`{"detail": "未登录或 token 缺失"}`），不走信封。
- ⚠️ 角色不符时返回 **HTTP 403**（`{"detail": "当前账号角色（student）无权访问该接口"}`），同样不走信封。
  受角色闸门保护的地址：`/teacher`、`/analysis`、`/question`、`/intervention`、`/report`、`/admin` 六个前缀，
  以及 `/agent/ingest/{stats,bank,file}`（这三个是逐个端点挂，因为同一前缀下的 `/agent/status` 对学生开放）。

### 1.3 错误文案（前端据此提示）

| 场景 | message |
| --- | --- |
| 登录账号不存在 | `账号不存在` |
| 密码错误 | `密码错误，请重试` |
| 新密码过短（<6） | `新密码至少 6 位` |
| 其他异常 | 返回可读中文 `message`，前端 `Toast` 直接展示 |

### 1.4 列表分页

列表类接口统一返回 `{ total, list: [...] }`，支持 `page`（从 1 起）/ `size`。

> **特例**：`GET /teacher/classes` 返回**裸数组** `[{classId,name}]`（非 `{list}`），前端已兼容。**新增接口请勿混用两种形态。**

### 1.5 身份来源

身份（userId / role）由后端从 JWT 解析，**不要**依赖前端在 query/body 重复传 userId。

**「按知识点取资源」的统一口径（学生端资源中心 / 知识图谱 / 教师端共用，2026-09-22 统一）**

- 一条资源可挂多个知识点：主挂载点 `resources.kp_id` + 多标签 `resources.kp_ids[]`（JSON 数组）。
- `kpId` 过滤 = **两者任一命中**（`services/catalog_helpers.resource_hits_kp()`），与学习路径 `/graph/path`
  的 `resCount`（`services/learning_path.resource_count_map()`）**完全同源**，
  保证「左侧标记 N 个资源」与「点进去实际看到的条数」一致。
- 典型场景：教材 `R006 第2章 线性表（教材）` 主挂载 `KP003`，`kp_ids=["KP003","KP004","KP005"]`，
  则点「线性表 / 顺序表 / 链表」三个知识点都应出现它（同一资源对同一知识点只计一次、不重复展示）。
- ⚠️ 修复前：`/student/resources?kpId=` 只匹配 `Resource.kp_id == kpId`，多标签资源被漏掉
  （现象：左侧标 6 个、点进去只有 4 个）。
- 相关接口：`GET /student/resources?kpId=`、`GET /graph/kp/{kpId}` 的 `resources`、
  `GET /teacher/graph/kp-detail` 的 `resourceCount`。

**驾驶舱结构**
```jsonc
// response.data
{ "overview": { "courseProgress", "currentNode": {...}, "streakDays", "todayStudyMinutes", "status" },
  "coreMetrics": { "completionRate", "masteryRate", "goalAchieveRate", "updatedAt" },
  "todos": [ ... ], "weakPoints": [ ... ], "suggestedQuestions": [ ... ], "recentActivities": [ ... ] }
```

## 5. 智能练习 `/practice`

| 方法 | 路径 | 状态 | 说明 |
| --- | --- | --- | --- |
| GET | `/practice/modes` | ✅ | 练习模式列表（含推荐题量） |
| GET | `/practice/kp-pool` | ✅ | 各知识点的**已发布题量**（`{counts:{kpId:题数}, total}`）；顺序练习据此隐藏无题的知识点 |
| POST | `/practice/sessions` | ✅ | 创建练习会话（组卷） |
| GET | `/practice/sessions/current?mode=` | ✅ | 当前进行中的练习存档（无则 `null`） |
| GET | `/practice/sessions/{sessionId}/questions` | ✅ | 取题 |
| POST | `/practice/answers` | ✅ | 提交单题 → 即时判分 + 解析 + 知识点定位树，并写 `answer_records`、触发预警重算 |
| POST | `/practice/sessions/{sessionId}/finish` | ✅ | 结束练习，返回练习报告 |
| GET | `/practice/wrong-book?mastered=&errorType=&page=` | ✅ | 错题本 |
| GET | `/practice/wrong-book/{qId}/detail` | ✅ | 错题详情（含相似题、推荐资源、图题规格） |
| DELETE | `/practice/wrong-book/{qId}` | ✅ | 移出错题本（标记已掌握） |

**组卷请求**
```jsonc
{ "mode": "weak|order|random|wrong", "kpIds": ["KP52"], "count": 10, "difficulty": 3 }
```
**组卷响应 / 各模式取题范围**（2026-09-24 起）
```jsonc
// response.data；组不出题时 questions=[] 且 total=0，用 emptyReason 区分原因
{ "sessionId": "PS...", "mode": "random", "total": 15, "questions": [] }
{ "sessionId": "", "mode": "random", "total": 0, "questions": [], "emptyReason": "random_scope_empty" }
```
> - `weak`：只取 `kpIds` 指定的知识点（**不再扩散到同章**）；`kpIds` 不属于当前课程 → 空池。
> - `random`：只取**「学过且做错过」**的知识点（加权正确率 < 100%，限当前课程）；已学全对 / 从未作答 → `emptyReason: "random_scope_empty"`。
> - `wrong`：只取该用户在当前课程的错题。
> - 带 `kpIds` 时池内排序 = 知识点顺序 → 做错过 → 难度升序 → 同档随机；其余模式为池内随机抽样。
> - `weak` 且未带 `kpIds`（无可定位薄弱点）→ `total=0`（不带 `emptyReason`，前端按"无可定位薄弱点"提示）。

**答题请求 / 响应**
```jsonc
// request
{ "sessionId": "PS...", "qId": "KHD047", "answer": "B", "durationSeconds": 42 }
// response.data
{ "qId", "correct", "rightAnswer", "analysis", "kpPath", "classCorrectRate", "avgSeconds", "masteryDelta" }
// 填空题额外返回 blankResults: [{ "index": 1, "correct": true, "expect": "先进先出 / FIFO" }]
// 组卷题目 type=blank 时 options 为空，blanks 只有空位序号 [{ "index": 1 }]，不含标准答案。
// 提交 answer 为 JSON 数组字符串，如 "[\"先进先出\",\"后进先出\"]"。选择题仍提交选项字母，判分不变。
```

## 3. 三大课程图谱 `/graph`（师生共用）

| 方法 | 路径 | 状态 | 说明 |
| --- | --- | --- | --- |
| GET | `/graph?courseId=&type=knowledge\|problem\|goal&userId?` | ✅ | 查询图谱（三类图谱均有真实数据） |
| GET | `/graph/kp/{kpId}` | ✅ | 知识点详情（含**知识点介绍** `summary`、前后置、挂载资源、习题统计、真实学情与课程均值） |
| GET | `/graph/path` | ✅ | 基于前后置关系的推荐学习路径 |

> `resources`（挂载学习资源）与 `resCount`（学习路径标记的资源数）同口径：主 `kp_id` + `kp_ids` 多标签都算命中，
> 见 §4「按知识点取资源的统一口径」。图谱右侧「挂载学习资源 N 个」因此与学习路径左侧标记数一致。

```jsonc
// GET /graph response.data → Graph
{ "graphType": "knowledge",
  "categories": [ { "name": "已掌握", "color": "#22c55e" },
                  { "name": "学习中", "color": "#6366f1" },
                  { "name": "待加强", "color": "#f59e0b" },
                  { "name": "未开始", "color": "#64748b" },
                  { "name": "薄弱预警", "color": "#ef4444" } ],
  "nodes": [ { "id":"KP01", "name": "数据结构概述", "category":1, "mastery":13.3,
               "difficulty":2, "isKey":false, "hours":0, "x":25.6, "y":1.25 } ],
  "links": [ { "source":"KP001", "target":"KP002", "relation":"pre" } ] }
```
> - `mastery` 由 `answer_records` + `resource_progress` **实时计算**（非种子静态值）。
> - `nodes[].category`（知识图谱）是按学生真实学习状态计算出的**状态下标**（0 已掌握 / 1 学习中 /
>   2 待加强 / 3 未开始 / 4 薄弱预警），前端据此给节点上色；阈值见
>   `数据模型与字段说明.md` §2.3。未登录时统一按 3（未开始）返回。
> - `x` / `y` 为教师在「图谱编辑」里布点的坐标（为空则前端退回力导向布局）。

**推荐学习路径（`GET /graph/path`）**
```jsonc
// response.data
[ { "step":1, "kpId":"KP001", "name":"数据结构概述", "chapter":"第1章 绪论",
    "status":"doing", "hours":1, "mastery":13.3, "resCount":3, "progress":13.3,
    "quizMastery":0, "quizAnswered":false, "locked":false, "lockReason":"" } ]
```
> - `resCount` **以 `resources` 表为准实时统计**（主 `kp_id` + `kp_ids` 多标签都计入，
>   同一资源对同一知识点只算一次），不再直接读 `learning_paths.res_count` 这个派生缓存
>   （只在教师端上传/删除资源时同步，学生端会长期停在旧值 0）。返回前会把该生
>   过期的 `res_count` 一并回写，保证缓存与实物一致。
> - 前端「推荐学习路径」的章节行资源数按**去重后的资源条数**统计（同一资源挂多个知识点只算一次），
>   因此章节合计可能小于各知识点之和。

| PUT | `/student/messages/{msgId}/read` | ✅ | 标记消息已读 |

**资源学习进度写入（`POST /student/resources/{resId}/progress`）**
```jsonc
// request.body
{ "progress": 0-100,          // 完成百分比（服务端与旧值取 max，不回退）
  "position": 12,             // 视频=秒；文档/PPT=页码
  "watchedDelta": 3 }         // 可选：本次上报周期内「真正播放」的秒数，仅视频使用
```
> - `watchedDelta` 由前端按播放时间轴累加（暂停/缓冲/拖动都不计），服务端只把它累计进
>   `resource_study_log.watch_seconds`（当日观看时长 → 驾驶舱「今日累计学习」）。
>   缺省时退回「`position` 增量」，并做单次 ≤300 秒的上限保护，避免拖动进度条虚增学习时长。
> - 视频弹窗播放前会等到「整段缓冲完成 / `canplaythrough`」再播放与记录，
>   加载期间不写任何进度；记录点（`position`）即下次进入时的续播位置，已完成视频从头重播。
> - 静态资源目录 `/resources/**` 由后端按 HTTP **Range** 提供（`Accept-Ranges`/`206`/`416`），
>   否则浏览器把视频当不可定位流，无法跳转续播、每次都要从 0 字节重下。
> - ⚠️ `resource_progress` **没有 (user_id, res_id) 唯一约束**，历史并发上报会留下重复行
>   （同一资源两行，一行 0% 一行真实进度）。因此：
>   读一律走 `services/resource_progress.py::progress_map()`（同资源只取 `progress/position` 最优的一行），
>   写走 `consolidate()`（把重复行合并成一行并保留最大值）。前端 `save()` 也做串行上报（同一时刻只发一个请求）。
>   要彻底根治需要给该表加唯一约束 —— **属于表结构变更，需先确认**。


**驾驶舱结构**
```jsonc
// response.data
{ "overview": { "courseProgress", "currentNode": {...}, "streakDays",
                "todayStudyMinutes", "todayStudySeconds", "todayPracticeSeconds", "todayResourceSeconds",
                "status" },
  "coreMetrics": { "completionRate", "masteryRate", "goalAchieveRate", "updatedAt" },
  "todos": [ ... ], "weakPoints": [ ... ], "suggestedQuestions": [ ... ], "recentActivities": [ ... ] }
```

> - `todayStudySeconds` = 当天练习用时（`practice_sessions.duration_seconds`，进行中的会话按已答题用时合计）
>   + 当天视频观看秒数（`resource_study_log.watch_seconds`），按**本地日历日（东八区）**统计；
>   驾驶舱徽标「今日累计学习时长」即取该字段，并由 `/student/study-duration` 每 30 秒轻量刷新。
> - `todos[].target` 为前端已注册视图名：`resource`（继续学习，带 `kpName` 定位知识点）/
>   `practice`（继续挑战，带 `sessionId`） / `graph` / `alerts`。
> - `recentActivities` 由 `practice_sessions`（练习）与 `resource_progress`
>   （视频/课件/文献学习，`type: "resource"`）合并按时间倒序，各取最新若干条。

## 8. 归因与错题分析 `/analysis`

| `draft` | `{ draft_id, status, errors, payload }` |
| `log` | 过程事件（原 `text` 类型） |
| `action` | 待批准写操作卡片（P2c）：`{ actions:[{kind:'confirm', actionId, tool, summary, impact, status}] }` |
| `done` | `{ batchId, draftIds, demo, count }` |
| `error` | `{ message }` |

> `demo: true` 表示当前未配置 `LLM_API_KEY`，处于演示模式。
> **注意（P2c）**：`save_question_draft` 是写操作，会先变成 `action`（`kind=confirm`）的**待批准卡片**——此时 `draft` 事件不会推、草稿也不会落库；用户点「确认执行」（`POST /agent/actions/{id}/approve`）之后才写入草稿箱。演示模式同样如此。

### 10.3 停止生成（三端共用）

```
POST /ai/chat/stop            （学生端 / 教师端答疑）
POST /admin/agent/chat/stop   （管理员端智能助手）
body: { sessionId }
→ { code:0, data:{ stopped: true, sessionId } }
```

协作式取消：置一个内存标记 → 本轮生成在**下一个检查点**收尾，并把**已经生成的部分**作为回答落库
（刷新后看到的是被停止的那一版，不是完整版）；SSE 的 `done` 事件带 `stopped: true`。
真实模式下若模型还在产 token，回调会直接抛异常**展开底层流**（关闭上游 HTTP 请求，不再继续消耗 token）。
会话归属校验：非本人 / 非当前课程（管理员为「非本人 / 非平台级」）→ **404**；
`sessionId=new`（还没建会话）→ `stopped:false` 不报错。

> 前端形态（主流智能体形态）：生成中发送键变成「停止」（方块图标 + `title="停止生成"`），
> 点击即调本接口并中止前端 SSE 连接；已显示的部分保留在气泡里，不报错、不提示失败。
> 三端（学生 / 教师 / 管理员答疑页）共用 `assets/js/shared/agent-chat.js`，因此行为一致。
> 局限：`AGENT_RUNTIME=sdk` 运行层暂未接入（该运行层非默认）。
